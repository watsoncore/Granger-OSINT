# Проверка GrangerPet 1.0

Проверено 27 октября 2026 года на Windows 11 x64, сборка ОС 26200, масштаб 125%.

## Готовый бинарник

`dist/GrangerPet.exe` — настоящий PE32+ AMD64, подсистема Windows GUI, 50 050 072 байта.

SHA-256: `a7099c87832501685701ee9e7ebd46c2d637bf4c9592d1682b8b526d39b38571`.

- Launcher и персонаж запущены из EXE в пустой рабочей папке, с новым профилем и PATH только `C:\Windows\System32`. Оба процесса завершились с кодом 0; свежие журналы подтверждают запуск.
- Через настоящий интерфейс EXE нажата кнопка «Запустить Гермиону». Отдельный процесс сообщил состояние Idle и меняющиеся кадры; Launcher показал фактическое состояние запуска.
- Закрытие Launcher оставило тот же процесс персонажа работающим. Повторное открытие Launcher обнаружило его, дополнительного экземпляра не возникло.
- Кнопка «Остановить Гермиону» завершила процесс. Кнопка выхода закрыла Launcher.
- Исходники, отдельные изображения и установленный Python для работы EXE не используются: ресурсы, Python и Qt упакованы внутрь.

Машинный отчёт о бинарнике: `dist/binarysmoke.json`. Воспроизводимая проверка: `python scripts/smoke_exe.py` после сборки и закрытия запущенных экземпляров.

## Автоматические проверки

`python -m pytest -q`: **37 тестов и 13 подслучаев прошли, пропусков нет**.

Проверены построение и валидация Dork, IDNA, точные фразы, исключения, URL, обработка ответов/ошибок API, асинхронная панель, сохранение настроек, независимые процессы, защита от дубликатов, восстановление после аварийного завершения, состояния и завершение анимаций, клики, перемещение и сохранение позиции.

Реальный тест Launcher с настоящим QProcess и PetWindow подтвердил цепочку: нажатие кнопки → запуск персонажа → закрытие Launcher → персонаж работает → повторный Launcher → тот же PID → выход завершает персонажа.

`python scripts/verify_assets.py`: все семь последовательностей содержат по 25 прозрачных кадров 256×256 с изменяющимся содержимым. Всего 175 кадров. Частота воспроизведения исходных последовательностей отделена от частоты обновления окна.

## Нативная проверка Windows

`python scripts/smoke_windows.py`: **21 проверка прошла**. В частности:

- Нативное окно имеет стили прозрачности, отсутствующей рамки и положения поверх окон.
- Windows `WindowFromPoint` возвращает окно персонажа на видимом пикселе и нижележащее окно на прозрачной области: проверено настоящее пропускание кликов.
- Проверены открытие/повторное закрытие панели, Walk при перетаскивании, запись/восстановление положения, реакции на координаты курсора, семь последовательностей, согласование состояний поиска и завершение процесса.

Машинный отчёт: `output/qa/validation.json`. Снимки: `output/qa/launcher.png`, `output/qa/pet_states.png`. Этот сценарий проверяет исходные классы в настоящем Windows GUI; отдельная проверка EXE описана выше.

Реальный поиск без API дополнительно проверен без подмены браузерного вызова: приложение прошло Thinking → Working → Happy, браузер Zen открыл страницу с заголовком `site:example.org - Поиск в Google`. Выдача в панели при этом не изображается.

## Графика и границы проверки

Персонаж, Idle и Walk действительно созданы инструментами AutoSprite. Hover, Happy, Thinking, Working и Error получены воспроизводимым Qt-ригом из того же рисунка: отдельные движения взгляда, головы, руки, выражения лица и страницы книги. Источники и запрос записаны в `grangerpet/assets/provenance.json`. Успешных ресурсов ImageGen в поставке нет.

Не проверены с действующим аккаунтом: живая выдача Google Custom Search JSON API и её квоты. Её парсинг, карточки и ошибки проверены на явно тестовых ответах; они не выдавались за найденные сайты.

На отдельных устройствах не проверялись Windows 10, другие масштабы DPI и несколько мониторов. Физическое наведение и перетаскивание не проходили полный ручной сценарий в EXE; обработчики движения и перемещение проверены автоматическими Qt-тестами. Обновление направления взгляда и возврат в Idle проверены с контролируемыми координатами курсора. Пункты контекстного меню реализованы, но отдельно не проверены.
