# Переносимое защищённое хранилище

## Обнаруженные зависимости

До этого обновления короткие API-ключи сохранялись через Windows Credential
Manager (`Advapi32`), длинные сессии — через DPAPI (`Crypt32`). DPAPI также
защищала историю, сохранённые диалоги, checkpoints и непрочитанные уведомления.
Публичные evidence-журналы и локальные документы Canvas были обычными JSON/MD.
Внутренние уведомления уже реализованы средствами Qt: Toast, Action Center,
WinRT, Microsoft account и Microsoft cloud для них не используются.
Телеметрия этим обновлением не добавляется.

## Формат и ключи

`grangerpet/portable_vault.py` использует `cryptography==50.0.2`, Argon2id
(64 МиБ, 3 прохода, 4 lanes, случайная соль 16 байт) и AES-256-GCM.
Это второй рекомендованный профиль RFC 9106 для ограниченной памяти.
Параметры чтения фиксированы и проверяются до KDF; подмена заголовка не может
заставить приложение выделить произвольный объём памяти.

Парольная фраза должна содержать минимум 12 символов, максимум 4096 байт UTF-8.
Она вводится пользователем, не генерируется из имени компьютера и не хранится
рядом с контейнером. Производный ключ находится только в памяти открытого
процесса. Он шифрует версионированный контейнер `.gpx`, содержащий секреты и
отдельный случайный ключ данных. Заголовок контейнера аутентифицирован AEAD.
Каждая запись контейнера и каждого отдельного файла использует новый случайный
96-битный nonce. Изменение пароля создаёт новую соль и новый производный ключ,
сохраняя ключ данных: переписывать всю историю не требуется.

После каждой записи выполняется flush/fsync и атомарная замена. На диск не
записывается открытая промежуточная версия. Файловая блокировка между процессами
Granger предотвращает потерю обновлений контейнера от лаунчера и питомца;
повторная запись сначала перечитывает актуальную зашифрованную версию.
Смена пароля в одном процессе требует повторной разблокировки другого процесса.

Контейнер располагается в `GrangerPet/vault/<hash-namespace>.gpx`.
Отдельные защищённые данные — в `GrangerPet/portable-data/` с прежней структурой
путей. Совместимые имена `.dpapi`, `.json`, `.md` сохранены; содержимое в
переносимом режиме имеет сигнатуру `GRANGERDATA1` и зашифровано AES-GCM.
Расширение файла само по себе не означает открытый текст.

## Явная миграция

Существующий профиль работает по прежней схеме, пока пользователь явно не
создаст переносимое хранилище и не задаст пароль. Чужие реальные данные и ключи
при тестировании автоматически не мигрируются. После появления `.gpx` обычное
чтение и запись секретов/защищённых файлов больше не используют Windows API.
Заблокированное хранилище возвращает ошибку; возврата к DPAPI или plaintext нет.

При миграции выполняются следующие действия:

1. Проверка парольной фразы и чтение известных секретов legacy-адаптером.
2. Чтение истории, именованных диалогов, checkpoints, непрочитанных уведомлений,
   evidence-журналов и Canvas из известных каталогов профиля. Символические
   ссылки, выход из каталога, превышение размера и повреждённый JSON отклоняются.
3. Шифрование копий в отдельном staging-каталоге. Каждый файл расшифровывается
   обратно и сравнивается с исходными байтами; запись перечитывается с диска.
4. Публикация `portable-data`, затем атомарное создание проверенного `.gpx`.
   Создание контейнера является точкой активации переносимого режима.

Legacy-файлы и записи WCM **не удаляются и не перезаписываются**. Это резервные
оригиналы, которые могут быть нужны при восстановлении. Следовательно, прежние
открытые evidence/Canvas-файлы сохраняют свой прежний уровень защиты; миграция
не заявляет, что исторические открытые копии исчезли. Новые записи идут только
в зашифрованное переносимое хранилище. Удаление старых копий не автоматизировано.

При сбое записи до активации старый профиль остаётся действующим. Если процесс
завершился между публикацией файлов и контейнера, повторный запуск миграции
сохраняет осиротевший каталог под `.portable-recovery-<id>` и повторно читает
неизменённые оригиналы. Частично повреждённые legacy-данные блокируют активацию;
ошибка не превращается в «успешную миграцию».

Индекс текущего диалога содержит только непрозрачный ID. Заголовки диалогов
извлекаются в память из шифротекста. Техническая SQLite-статистика использования
сохраняет прежний формат: она не содержит сообщений, ключей и HTTP-заголовков.
Настройки без секретов также остаются в переносимом JSON. Явный экспорт Canvas
в выбранный пользователем `.md` создаёт открытый UTF-8 документ по назначению
операции; автоматическое внутреннее сохранение Canvas зашифровано.

## Ограничения и восстановление

После перезапуска требуется повторная разблокировка парольной фразой. Каждый
независимый процесс разблокируется отдельно; пароль не передаётся через IPC.
Без парольной фразы восстановить `.gpx` нельзя. Рекомендуется сохранить резервную
копию контейнера вместе со всем `portable-data` в защищённом пользователем месте.
Обновление не создаёт скрытого recovery-ключа и не отправляет данные в облако.
Потеря одновременно контейнера и резервной копии означает потерю ключа данных.

Lock удаляет ссылки на ключи в хранилище и запрещает новые операции. Python и Qt
не гарантируют физическое обнуление всех копий строк, ранее показанных в UI,
буфера обмена или памяти ОС. Очистка интерфейса должна выполняться оболочкой;
строгое завершение работы процесса остаётся границей удаления таких копий.
Перенос формата проверен копированием контейнера и данных без вызовов Windows
API; запуск полного Qt-приложения на Linux/macOS в этой среде не проверялся.

## Проверки

`tests/test_portable_vault.py` выполняет настоящие Argon2id/AES-GCM операции
с синтетическими данными: UTF-8, create/unlock/lock, неверный пароль, порча
контейнера/файла, отклонение опасных KDF-параметров, уникальные nonce, смена
пароля с чтением прежних файлов, конкурентные экземпляры, сбой атомарной записи,
перезапуск, перенос в другой каталог без Windows API, отсутствие plaintext
fallback, восстановление прерванной миграции, зашифрованные evidence/Canvas и
непрочитанные уведомления. На Windows дополнительно выполняется настоящая
миграция тестового WCM/DPAPI-профиля и отказ на повреждённых legacy-данных.
Реальные пользовательские секреты в fixtures не используются.

Документация примитивов: [Argon2id](https://cryptography.io/en/latest/hazmat/primitives/key-derivation-functions/#argon2id),
[AESGCM](https://cryptography.io/en/latest/hazmat/primitives/aead/#cryptography.hazmat.primitives.ciphers.aead.AESGCM),
[RFC 9106, параметры](https://www.rfc-editor.org/rfc/rfc9106.html#section-4).
