# UI reconstruction — проверенные изменения

Исходная точка: `034e289`. Изменяется существующий React/Qt интерфейс Granger-OSINT. Нового приложения, чата или лаунчера нет.

## Аудит

- Frontend: `frontend/src/App.tsx`, компоненты в `frontend/src/components/`, Vite, React 19, Radix, Lucide, Motion, react-markdown/remark-gfm, существующий TanStack Virtual.
- Нативные окна: `grangerpet/window_chrome.py`, `theme.py`, `typography.py`; React загружается через существующий `DesktopSurface` и закрытый WebChannel.
- Локальный шрифт: **Manrope Variable**, реальные веса 200–800, `frontend/public/fonts/Manrope-Variable.ttf`, лицензия OFL рядом. Точное семейство недоступного референса не устанавливалось. Дополнительных пользовательских навигационных SVG/PNG/WebP не найдено. Уже имеющиеся `brand-hermione.png`, `hermione.png` и иконка EXE сохранены.
- В исходном текущем frontend кнопки окна уже использовали Lucide SVG, нативный HeaderControl рисовал линии QPainter. Воспроизвести именно исторический квадрат из отсутствующего в новом вложении скриншота нельзя. В обоих активных путях теперь используются SVG с одинаковой толщиной линий; Unicode-глифы для кнопок окна не нужны.
- Подтверждённая причина риска исчезновения персонажа: нативный Pet требует, чтобы dock был не меньше полного размера его окна; при уменьшении viewport/zoom такой прямоугольник может не поместиться. Один CSS overflow не решает это ограничение. Адаптация нативного размера реализуется отдельно в интеграционном этапе и должна проверяться с реальным Pet.

## Реализация

- Все цвета существующих `styles.css` и `typography.css` переведены на общие semantic tokens. `themes.css` содержит четыре палитры: тёмную, чисто чёрную, белую и монохромную. Монохромный режим не фильтрует исходное изображение персонажа: графические ассеты сохранены.
- «Внешний вид» в существующих настройках переключает тему без перезагрузки. Применение сохраняется обычной кнопкой «Сохранить», как другие настройки. Авторитетный параметр — `settings.ui_theme`; bootstrap поддерживает переданный нативной оболочкой `window.__GRANGER_THEME__`, затем локальный кэш. Нативные диалоги используют те же палитры через `apply_theme`/`style_for_theme`.
- Общие токены типографики задают 15 px для текста чата, 14 px для подписей/карточек, 13 px для вторичного текста и кода, 18/19/23 px для заголовков. Навигация 15 px/600, основной текст 500. Manrope подключён также в Qt с системным fallback при отсутствии ассета в несобранном checkout.
- `icons.tsx` — центральная карта существующих SVG для оконных действий и навигации, с точкой подключения будущих предоставленных ассетов. Фиктивных путей или пустых изображений нет.
- Убраны «ПЕРСОНАЛЬНАЯ OSINT-СРЕДА», «ВАША ГЕРМИОНА» и декоративная версия внизу лаунчера. Название окна и версия в настройках сохранены.
- Верхняя часть компактнее. Активная навигация имеет контрастную поверхность, границу, текст и иконку. Кнопка сворачивания навигации доступна также в узком режиме.
- Правая панель имеет явную кнопку сворачивания/восстановления. При узком viewport она сворачивается с сохранением этой кнопки. Dock ограничен доступной высотой; при размонтировании его предыдущий прямоугольник явно снимается через `layout {dock:null}`. Это не изменяет сохранённый размер desktop companion.
- Карточки — равные колонки Grid, растянутые по ряду flex-карточки с нижними действиями. Описания остаются полностью доступными. При большом каталоге отрисовывается страница из 24 карточек, фильтры работают по всему набору.
- `SourceInspector`: фактические источники текущей задачи (`task_sources`, с совместимым fallback), поиск, фильтры «Все/Прочитаны/Ошибки», группировка, URL, тип, статус, раскрываемая выдержка, переход к связанному ответу. При более 40 записях используется существующий virtualizer; вся коллекция остаётся в состоянии. Ключи записей стабильны, обновления не устанавливают scrollTop=0.
- «Прочитан» требует backend-флага `content_fetched` или явного статуса `read/readable/fetched/analyzed` для страницы без ошибки и без JavaScript shell. Сниппет, обнаруженный URL и общий `success/verified` не становятся прочитанной страницей.
- Настройки содержат обычные поля разрешённых GEOINT endpoints, персональный VirusTotal credential control, а также native-only операции vault. Парольная фраза не вводится в React.
- Виртуализация длинного чата, инкрементальные observer сообщений, публикация только изменений и остановка публикации скрытой страницы сохранены.

## Проверки этапа

- `npm run test`: **69 passed**, 10 файлов, включая новые проверки фильтров/статусов, 500 источников с ограниченным DOM, тем и native vault actions.
- `npm run build`: успешен. Существующее предупреждение Vite о JS chunk >500 kB остаётся; это не ошибка сборки.
- `python -m pytest tests/test_ui_themes.py tests/test_window_modes.py tests/test_unified_ui.py -q`: **13 passed** в отдельных выполненных проверках. Проверены реальные Qt SVG-изображения, четыре palette, переключение окон, кириллица в локальном шрифте.
- Контраст текста `text/secondary/muted` к `background/surface/raised` и акцента к его foreground во всех нативных палитрах — не ниже **4.5:1**. Нейтральность всех цветов mono проверяется по RGB.
- `scripts/qa_ui_reconstruction.py --output output/reconstruction-qa/ui-source-3`: **52 проверки пройдены**. Реальные production OsintPanel, Launcher, QtWebEngine, WebChannel и собранный React; изолированный APPDATA, 1000 синтетических UI-сообщений и 120 явно помеченных источников. Это не live OSINT и не проверка финального EXE.
- Проверены размеры окна 1920×1080, 1600×900, 1366×768, 1280×720, 760×560 и WebEngine zoom 80/100/125/150%. Горизонтального overflow нет; панель либо имеет геометрию, либо доступна явная кнопка восстановления. Размеры окна/zoom не меняют системный Windows DPI.
- Сняты и визуально просмотрены собственные Qt-скриншоты, включая белый чат, тёмные карточки, монохромный лаунчер и узкий/увеличенный viewport. По первому проходу обнаружен и исправлен преждевременный вызов layout до подключения WebChannel, который показывал ошибку в лаунчере.

## Границы доказательств

Source UI harness не создаёт настоящий Pet и не подтверждает его видимость/масштабирование. Финальный EXE, физический Windows DPI 100/125/150/200%, полноценный sprite-in-dock и итоговая интеграция проверяются основным релизным этапом. Исторический скриншот со сломанным glyph в текущем вложении отсутствует; причина его появления не объявляется установленной.
