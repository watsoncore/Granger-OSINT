# Panoramax в Visual GEOINT

`map_panoramax` дополняет выбранные бесплатные стадии Waypoint. Используется
публичный STAC endpoint `https://api.panoramax.xyz/api/search`, как в проверенном
Waypoint commit `502318a7da42bdc38af2ad2f87152492dbf9d671`. Адаптер написан
самостоятельно поверх общего `web_http`; код Panoramax/его backend не включён.
[Официальная документация API](https://docs.panoramax.fr/backend/) описывает
получение коллекций, снимков и метаданных; дополнительный OAuth не используется.

Вход: latitude/longitude, radius_m100–2000 (по умолчанию500), limit1–10
(по умолчанию5). Один bounded запрос без перехода по страницам. Бокс с переходом
через180° отвергается. Сохраняются точный ID, координаты эталонного снимка, дата,
лицензия, автор, ссылки thumb/sd и provenance. DNS pinning, лимиты, отмена,
rate/backoff и пятиминутный кэш общие с остальными публичными адаптерами.

Пиксели не скачиваются и снимок пользователя не передаётся источнику.
Лицензия проверяется для каждой записи отдельно: наличие кода под MIT не даёт
лицензию на все фотографии. При живой проверке район Парижа вернул две записи
с `etalab-2.0` и авторской атрибуцией. Полная запись теста:
`output/integrations19/panoramax-registry-live.json` (локальные QA-данные).
Близость архивного снимка к кандидату модели не доказывает совпадение места.

Связи графа помечены `reference_source_reports_coordinate`. Они относятся к
эталонному снимку, а не к геолокации исходного фото пользователя. DISK/LightGlue
можно отдельно применить к двум явно выбранным защищённым вложениям; автоматическая
массовая загрузка улиц и reranking всех изображений не реализованы.

Проверены неверные параметры, массивы вместо объектов, недопустимые координаты,
неизвестные поля, запрет private asset URL, пустое покрытие, сохранение автора и
лицензии и единственность запроса. Это тесты контракта, не оценка точности модели.
