# Canvas commit acknowledgements and shutdown recovery

Canvas changes use a stable 32-hex `mutation_id` and an `await_commit` acknowledgement. A successful acknowledgement is delivered after the immutable encrypted revision is saved. Repeating the same mutation and payload returns its existing receipt without adding another revision. A reused mutation ID with a different payload is rejected. A real storage compare-and-swap conflict returns `analyst_canvas_revision_conflict` and the observed current revision; the newer disk revision is preserved.

Ordinary panel close hides the existing page. Actual `DesktopSurface.shutdown()` keeps the page and QWebChannel alive while requesting `window.grangerCanvasQueue.prepareShutdown()`. The renderer freezes new intake and drains its existing queue. The native side polls `snapshot()` every 40 ms and allows at most 2.5 seconds for both renderer intentions and the current native save to finish. A reentrancy guard prevents nested shutdown drains.

Unsaved inspector labels and Markdown are held by owner (`canvas ID | visual node ID`) in memory. `registerCanvasDraftProvider(provider)` registers their inert recovery intentions once; ordinary queue snapshots and metrics never call the provider. `prepareShutdown()` captures providers once, after freezing editor intake. Existing nodes become `annotate` intentions, while text for a new, uncreated object becomes a manual `analyst_note`. The shutdown path does not enqueue this text or turn it into accepted source facts. These intentions are held for explicit recovery after reopening.

If the queue or captured editor text remains nonempty, native code atomically saves an encrypted, inert draft below the existing protected canvas directory as `pending-<id>.dpapi`. It accepts at most 1024 intentions and 32 MB of UTF-8 JSON, including 300 full-length Unicode editor notes and queued actions. Finite values, known canvas operations and operation-specific fields remain mandatory. Client paths, executable commands and credential fields are rejected. The native in-flight intention is included if the renderer snapshot omitted it. Original conversation files are not involved.

A provider intention identical to an already accepted queued save uses that save's existing mutation ID. Accepted creation keeps its exact pending payload until acknowledgement, so it is not also exported as a second manual note. Shutdown snapshots keep stable tokens, and an acknowledgement removes the captured duplicate even if the editor callback has not yet cleared its memory entry. Explicit save/create clears only the matching text after a successful acknowledgement; failure, discard and a newer edit retain the original or newer draft. At 300 dirty owners, editing an additional owner is refused with a visible explanation. Existing drafts are never silently evicted and can still be edited or saved.

Each successful native canvas mutation stores its ID in the last 128 `mutation_receipts` of the document, including initial document creation. A save can finish after the bounded drain expires. Recovery reads the newest immutable document receipts and filters those already committed IDs, so a late save is not repeated and an already-created project is not created again.

Finite actions are `research_canvas_queue_recovery {}` (`queue_read` alias) and `research_canvas_queue_clear {draft_id}`. Recovery reads/decrypts off the GUI thread and completes its deferred reply with `{draft_id,intents,current?,error}` or null. Reading recovery never executes its saved tools, AI requests, edits, imports or file pickers. The renderer holds recovered intentions for an explicit user retry. That retry opens the owning canvas before applying a recovered or cross-project intention; subsequent intentions for another canvas wait for another explicit retry. Recovered/unsent intentions keep their receipt token. A real failed CAS requires an explicit reload/rebase and a new token because the live bridge caches its failed response. Corrupt draft ciphertext is retained without rewriting it.

`tests/test_master_v3_bridge.py`, `tests/test_registry_v3.py` and `tests/test_canvas_pending_v3.py` exercise actual Qt queued replies and encrypted temporary stores, without opening the user's profile. Checks include durable ACK/replay, actual stale-store revision conflicts, invalid IP rejection before Gansar launch, original image byte hashes/integrity failure, all 57 Maigret records through the registry, actual Surface shutdown ordering with a finite page fixture, bounded slow-save fallback and late-commit receipt filtering. These tests do not substitute for native/frozen WebEngine QA of the complete packaged app.
