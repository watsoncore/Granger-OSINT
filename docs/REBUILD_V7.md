# Granger-OSINT — Rebuild V7

V7 объединяет развёрнутое полотно, типизированный поиск по публичным источникам
и отдельный контекст DeepSeek для каждого расследования. Приёмка выпуска прошла
на собранных EXE в изолированных профилях Windows.

## A. Root causes

Развёрнутый граф оставался потомком прокручиваемых dashboard-панелей.
Ограничения высоты и overflow продолжали обрезать рабочую область. Полотно выводится
через portal непосредственно в корень окна. Панели открываются поверх него.

Повторный NFT-запрос терял выбранную операцию в просмотре результатов, а wallet
projection исключала активы. Теперь операция сохраняется до вставки, NFT имеют
отдельное представление, а квитанция различает новые узлы, связи, существующие
основания и наблюдения без самостоятельной карточки.

Контекст извлекался по лексическому сходству до строгого ограничения области.
Отбор теперь начинается с идентификаторов диалога, расследования и полотна.
Данные выбранных объектов передаются отдельно от видимого сообщения пользователя.

Нативная проверка выявила также перехват resize группы соседней карточкой,
скрытие её членов старым правилом проекции и конфликт двух CSS-ограничений
высоты окна результатов. Все три дефекта исправлены в рабочем коде.

## B. Graph Engine 2.0

Сохранена единая модель объектов, отношений и evidence. Гибридный renderer
рисует карточки Canvas2D. В плотном viewport рёбра рисует WebGL2, а в разреженном
viewport и при недоступности WebGL2 их рисует Canvas2D. Камера меняет uniform
и сохраняет GPU-буфер неподвижных рёбер при панорамировании. При обычном
масштабировании рёбра и карточки используют общие мировые координаты. Для
дальних меток фиксированного размера геометрия учитывает масштаб.
При фиксации перемещения пересчитываются связанные рёбра. Для локальных
изменений Qt-канал передаёт упорядоченные дельты с проверкой revision и scope.
При рассогласовании запрашивается полный снимок. Зашифрованное сохранение
остаётся полным и выполняется в worker.

Пять реализаций прошли 25 сравнительных серий в отдельной лаборатории Qt 6.11.1
на AMD Ryzen 5 5600H, 12 логических процессорах и AMD Radeon Graphics через
ANGLE D3D11. В каждой серии одинаковое дерево связей, карточки 240×128, PNG,
viewport и DPR, 80 программных обновлений камеры и перемещения.

| 5000 узлов | Подготовка, мс | JS-обновление p50, мс | RAF p50 / p95, мс |
|---|---:|---:|---:|
| Canvas2D | 0,2 | 7,1 | 16,7 / 18,1 |
| Pixi | 27,3 | 0,8 | 16,7 / 17,9 |
| Cytoscape | 1136,5 | 0,2 | 30,7 / 44,6 |
| React Flow | 1819,4 | 2,7 | 16,8 / 21,1 |

JS-время измеряет вызов SDK, RAF включает ожидание следующего кадра. Обе
метрики получены на тестовой сцене. Отдельно ELK 0.12.1 разместил 5000 узлов
за 2,23 с в worker. Максимальный интервал RAF основного потока был 16,8 мс,
высота раскладки составила 585 912 px. Выбран собственный гибридный renderer
с существующей семантикой карточек, редактирования и координат. React Flow,
Sigma, Graphology, Cytoscape и Pixi проверены в лаборатории под MIT. ELK
поставляется с выбором EPL-2.0 или GPL-3.0-or-later. Список зависимостей
приложения остался прежним. Для tldraw отдельно проверены условия production
лицензирования. [Условия tldraw](https://github.com/tldraw/tldraw/blob/main/LICENSE.md)

## D. Obsidian-style interaction

Ручные карточки, группы, перемещение и изменение размера, сворачивание,
соединение портов, направления и оформление отношений, Markdown, изображения,
поиск, undo/redo и существующие горячие клавиши используют тот же документ.
Уверенность ручной связи — оценка аналитика, а не подтверждение личности.
Наблюдения инструментов нельзя переписать как ручные утверждения.

Экспорт `.granger.zip` содержит исходный DTO, JSON Canvas 1.0 и оригинальные
изображения с контрольными суммами. Отдельный `.canvas` создаёт соседнюю папку
оригиналов. Импорт учитывает правки другого редактора вместо безусловного
восстановления устаревшего расширения. Внешние утверждения импортируются как
непроверенные. Приёмка через диалоги Windows восстановила обе карточки,
русскую заметку и исходный PNG из каждого формата. Сравнены байты оригинала.
[JSON Canvas 1.0](https://jsoncanvas.org/spec/1.0/)

## E. UI/UX

Обычные действия предлагают найти публичные профили, исследовать email,
компанию или криптообъект. Технический выбор сохранён в дополнительных
настройках. В основном username-маршруте используется Maigret. Остальные
движки сохранены в расширенном каталоге. Находки раскрываются отдельно,
фильтруются и вставляются с фактической квитанцией сохранения.

## F. Design system

Полотно использует тёмные стеклянные плавающие панели, отражающий верхний блик,
границы и контролируемое свечение выбора. Сохранены локальные шрифты с
кириллицей, темы, Reduced Motion и отключение эффектов. Декоративные blur
ограничены панелями. Спрайты, размеры и анимации персонажа не менялись.

## G. Typed forms

20 типов имеют предметные поля. Для компаний выбираются юрисдикция и вид
идентификатора, для кошельков — сеть, для профилей — URL/платформа, для заметок
— Markdown. Неизвестный HTTPS-профиль остаётся ручным непроверенным URL.
Форматная проверка номера не выдаётся за подтверждение регистрации. Компании
с одинаковым названием остаются отдельными кандидатами.

## H. OSINT workflows

Email workflow объединяет технические записи почтового домена, официальный
индекс публичного email GitHub и точные публичные упоминания Hacker News.
MX/SPF/DMARC не подтверждают существование ящика. Кандидаты GitHub не
объявляются установленной личностью. SMTP, регистрация, восстановление пароля,
утечки и угадывание username не используются. В EXE получены 3 наблюдения
Maigret и 6 записей email workflow. Вставка добавила 12 и 19 узлов соответственно.

Публичные профили и репозитории GitHub доступны через действующие адаптеры
официального API. Маршрутизатор использует тип объекта, введённое значение,
юрисдикцию и доступность инструмента. Подсказки действий описывают классы
источников и ожидаемые данные. В чате сохраняются ограничения по цели и
проверка аргументов инструмента. Статус evidence определяется результатом
проверки источника.

## I. Company intelligence

GLEIF ищет юридические лица с LEI по типизированному запросу. Британский
маршрут дополнительно использует Companies House при наличии собственного
ключа. SEC требует точный CIK. Юрисдикции KZ/RU имеют формы БИН/ИНН/ОГРН,
но GLEIF не заменяет национальные реестры и не гарантирует их покрытие.
Нативный поиск по названию вернул три кандидата и добавил 10 узлов. Точный LEI
вернул одну запись GLEIF по HTTP 200, с тем же идентификатором и provenance
в сохранённом графе. Оба запуска использовали реестровый маршрут.
[GLEIF API](https://www.gleif.org/en/lei-data/gleif-api/)

## J. Source adapter catalog

Добавлены исполняемые адаптеры GLEIF, SEC EDGAR, Companies House,
OpenCorporates, OpenSanctions, Crossref и OSV. Контракт источника показывает
регион, endpoint, аутентификацию, документацию, лицензию, версию парсера,
границы и последнее состояние. История health не хранит текст запроса.

Фиксированные HTTPS origins, проверка публичных DNS-адресов, отсутствие
редиректов, предел ответа 2 MB, rate gate, ограниченный cache и provenance
применяются при исполнении. Существующий reader разбирает инертные HTML,
JSON, XML/RSS, CSV, текст и текстовые PDF. PDF ограничены 20 страницами и
12 000 символами. Проверена упаковка QtPdf и динамической библиотеки Qt6Pdf.
В каталоге 84 инструмента с исполняемыми обработчиками, включая семь новых
адаптеров и два сценария. GLEIF, Crossref и OSV ответили HTTP 200.
SEC ответил HTTP 403, три адаптера ждут
ключей. Действующие Qt/PDFium notices и ссылки на исходники относятся к
собранному Qt runtime. [Лицензирование Qt PDF](https://doc.qt.io/qt-6/qtpdf-licensing.html)

## K. Gansar NFT

В реальном EXE обзор TON вернул 236 записей и добавил 422 узла и 858 связей.
Повторный NFT-запрос вернул 9 записей. Восемь записей уже существовали,
а новые наблюдения не требовали новых узлов или связей. Счётчик показал ноль,
представление активов открыло сохранённые NFT, а прежние основания пережили
перезапуск. Оба запуска дали частичные результаты. В сохранённом наборе восемь
NFT с идентификаторами и шесть ссылок на artwork. На снимке видны загруженные
миниатюры. Источник оставил поле отдельного контракта пустым. Карточка
показывает сеть и наблюдавшийся идентификатор актива.

## L. DeepSeek context isolation

Отбор ограничен диалогом, расследованием и полотном. Выбранная компания
передаётся с типом `organization`. Панель диагностики показывает только
идентификаторы и счётчики. Измерение на исходной Qt-сборке подтвердило
состав истории фактического SSE-запроса B. В нём присутствовали данные B,
а маркер A отсутствовал. Обычная реплика получила отдельный контекст.

В кандидате V7 два реальных ответа по синтетическим компаниям использовали
свои маркеры. В каждом scope диагностика показала две записи контекста и
только выбранный объект. Видимый чат содержал обычные сообщения. Действующий
шлюз отдельно подтвердил SSE и round trip двух `tool_calls`. Временная запись
QA в Windows Credential Manager удалена после проверки.

В этом парном прогоне V7 быстрее рисовала типичный кадр. Длинные кадры,
задержка ввода, private commit и запуск оказались хуже. Время запуска
сильно различалось между прогонами, поэтому одного парного замера
недостаточно для оценки его типичного значения.

В предыдущих семисценных прогонах V7 p95 рисования 5000 узлов составлял
58,6, 68,7 и 47,7 мс. Максимальный холодный кадр кандидата 6 на 50 узлах
занял 288,5 мс. В финальной серии полотно открылось за 11,18 с. Во время
жестов на 5000 узлах медианы составили 1101 МиБ RSS, 1952 МиБ private commit,
10,56% CPU и 5,10% по сумме GPU Engine. Плотный обзор использовал WebGL2,
сохранил 5000 объектов в модели и вывел 38 меток и кластеров с 204 рёбрами
при масштабе 1,49%. Некоторые подписи на этом масштабе перекрываются.

Время рисования измеряет работу Canvas в WebEngine. Задержка начинается
в обработчике события JS, активные интервалы исключают паузы от 100 мс.
Последние два показателя описывают активные кадры, а не FPS всей сессии.
RSS суммирует общие страницы. Private commit и счётчики драйвера GPU
приведены отдельно.

Исходный 18-минутный прогон завершился рассогласованием отображённого
документа. Промежуточный прогон кандидата 5 штатно остановлен после смены
реализации рендера. Кандидат 6 выполнил все 36 переключений за 20 минут,
но не прошёл порог роста private commit. Для 50 узлов медиана выросла
с 615 до 918 МиБ, для 5000 — с 593 до 711 МиБ. Графические поверхности
пересоздавались при каждом открытии документа. Теперь они остаются на месте,
состояние меняется по scope, а WebGL инициализируется в плотном viewport.
Первый прогон этого кандидата был прерван через 622,7 с. Отдельный непрерывный
прогон длился 1200 с, выполнил 36 переключений между 50 и 5000 объектами и
проверил вход и выход из полноэкранного режима Windows. После прогрева
медиана private commit снизилась с 1195 до 1186 МиБ для 50 объектов и с
1004 до 999 МиБ для 5000. Допуск составлял большее из 128 МиБ и 20% для
каждого размера. Все процессы теста завершились, временный профиль
успешного прогона удалён.

## P. Remaining limitations

- Live-доступ Companies House, OpenCorporates и OpenSanctions требует ключей
  соответствующих API и пока остаётся непроверенным.
- В реальном запросе SEC EDGAR ответил HTTP 403.
- Поиск KZ/RU использует доступное покрытие LEI. Для полноценной проверки
  БИН/ИНН/ОГРН нужны дополнительные разрешённые национальные источники.
- Состав корпоративного графа зависит от полей выбранного источника.
  Закупки, судебные дела и состав руководителей отдельных реестров остаются
  за пределами текущего покрытия.
- Пользователь видит описание действия, доступные инструменты и источники
  полученных записей. Отдельного предпросмотра полного плана сетевых вызовов
  DeepSeek перед исполнением нет.
- Сетевые Maigret/Gansar могут возвращать частичные результаты, 429 и ошибки
  провайдеров. Совпадение публичного идентификатора не устанавливает личность.
- Замеры ограничены текущим устройством, сценами и длительностью прогона.
  Стабильные 60 FPS во всех сценах не подтверждены. Подписи в плотном обзоре
  5000 объектов местами перекрываются.
- Кандидаты из аудита OSINT4ALL имеют собственные статусы проверки.
  Присутствие в списке само по себе не означает доступного инструмента.
