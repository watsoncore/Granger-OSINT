# Master Fix: реализация и измеренные проверки

Работа продолжает существующий Granger-OSINT. Gemini не возвращается; DeepSeek,
48 зарегистрированных инструментов, персонаж, четыре темы и Qt/React сохранены.
Это отчёт о пределах проверенных функций, а не заявление о полном покрытии сетей.

## Причина «Проверено: 1»

Старый счётчик показывал один запущенный адаптер Granger `blockchain`, а не
количество HTTP-запросов или внутренних коллекторов Gansar. Автоматический поиск
также обходил общий журнал расследования. Старый bridge связывал `max_txs` с
лимитом карточек20, обрезал нормализацию, выключал experimental enrichment и
ограничивал выполнение25 секундами. Отдельный NFT service не вызывался.

Контрольный EXE-прогон исходного TON-адреса:25,31 сек.,20 строк, счётчик1,
пустой investigation_id. В кандидате исправленный тот же маршрут дал200 строк,
сохранённое расследование,10 запущенных коллекторов и54 HTTP-запроса за45,73 сек.
Часть внешних источников осталась недоступной — этот статус не заменён успехом.
Коллекторы, HTTP-вызовы, URL и независимые подтверждения являются разными метриками.

## Архитектура

Использован настоящий `app.aggregator.analyzer` и `app.ton_nft.service` через
существующий изолированный worker.121 модуль совпадает с оригинальным Gansar на
`2caceea93bed4fffcfcca9a7e353007197e5f1f6`; оригинальный проект не изменяется.
Его SQLite, captures, production output и частные datasets не импортируются.
Публичный встроенный каталог используется без автоматического обновления.

Один `blockchain_gansar` принимает структурированные операции: profile, balances,
assets, transactions, nft, identity, contracts, labels, attribution, trace, cached.
Дополнительных карточек нет. Режимы задают реальные бюджеты времени/запросов/
пагинации; quick45/60, standard90/160, deep240/500. Лимит истории не превышает
50/200/1000 соответственно; разные коллекторы могут давать разные наборы событий.
Quick не исследует соседей без явно заданного depth; trace использует готовый
Gansar frontier с отдельными ограничениями соседей, истории и HTTP.

Полный DTO сохраняется отдельно под DPAPI/portable vault. Checkpoint содержит
только ограниченную карту непрозрачных идентификаторов. Нормализованные findings
не дублируют сырые тела ответов в каждом событии. NFT DTO сохраняет observations,
coverage и курсоры; повторный разрешённый запуск использует `_resume_report`.
Временная SQLite содержит только данные собственного запроса Granger.

## Граф и медиа

Активы/NFT, коллекции по контрактному адресу, Web3 records и contract observations
получают типизированные узлы с evidence. Одно имя коллекции не объединяет контракты.
Историческое владение не превращается в `owns` и не устанавливает личность.
Технические GitHub navigation/camo/avatar URL убраны из основных ветвей;
первичные данные остаются в evidence. Плотный граф отображает связный остов;
выбор/раскрытие узла возвращает его вторичные отношения без удаления данных.

Canvas сохраняет прежние фигуры, тонкие линии, pan/zoom/drag, фильтры, инспектор
и закреплённые позиции. Подписи проходят проверку пересечений; вторичные подписи
отношений показываются при подходящем масштабе/выборе.

Медиа берутся только из фактических avatar/image/OpenGraph/NFT metadata.
Backend использует pinned public DNS, проверки редиректов и robots; frontend
не получает права внешних HTTP-запросов. JPEG/PNG/WebP проверяются MIME и Pillow,
SVG/HTML отклоняются, лимит2 МБ/16 Мп, параллельность2. Оригинал и метаданные
зашифрованы; инспектор получает локальный JPEG-preview и исходную ссылку.
Загрузка начинается при выборе узла, а не для всех узлов графа.

Реальный Fragment WebP:1500×1500,136794 байта, SHA256
`fef89eba5e89bf83cb6d1c827d7bc4c5e96da263161b3fb4800958d21bdede73`.

## Исправления стабильности, выявленные при проверке

Снимки больших DTO больше не переполняют subprocess transport; последние
пригодные данные сохраняются при timeout/cancel. Хранилище принимало только50
строк одного envelope — теперь сохраняет до2000 проверенных findings.
Сохранение/проверка большого журнала и подготовка списков источников вынесены из
UI-потока. Результаты worker проходят прежние строгие контракты.

Исправлено чтение больших UTF-8 IPC-ответов до конца JSON-строки. Обычная отмена
UiJob не вызывает ошибочный глобальный toast. Асинхронное завершение media
заменяет graph state без изменения ранее опубликованного снимка.

## Оставшиеся объективные границы

Полный wallet/item/collection NFT engine имеется в Gansar для TON. Для других
сетей доступны только фактически реализованные token/transfer observations;
глобальная NFT-инвентаризация не имитируется. Base применяется для Basenames,
а не как дополнительная финансовая сеть. Нет универсального достоверного USD-
прайсинга всех активов. ENS/Lens/Basenames/EAS и публичные labels не устанавливают
личность. Отсутствие ответа не означает нулевой баланс или отсутствие объекта.

Для EVM без явно указанной сети применяется исходная маршрутизация Gansar;
это не автоматическое доказательство наличия адреса во всех шести EVM-сетях.
Конкретные сети проверяются параметром `chain`; каждая отдельно проверена live.

Публичные провайдеры ограничивают доступ, частоту и глубину истории. Никаких
обходов403/robots, бесконечных retry или скрытого использования приватных ключей
источников нет. GeoCLIP/Waypoint не запускаются при blockchain-поиске.

Финальные результаты EXE, чата, регрессии, сохранности и хэши сборки записываются
в отдельный итоговый manifest после завершения проверок кандидата.
