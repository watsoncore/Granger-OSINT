# DeepSeek V4 Flash в GrangerPet

Активная облачная интеграция использует модель `deepseek-v4-flash` через сторонний шлюз `https://api.aikeysforyou.com/v1`. Формат — OpenAI-compatible `POST /chat/completions` с `Authorization: Bearer …`. Это не прямой API OpenAI или DeepSeek; доступность модели, баланс и поддержка расширений определяются шлюзом.

В версии 2.5 сохранённый пользователем Windows-ключ использован для ограниченной живой проверки: обычный ответ, функция и возврат роли `tool`, два параллельных вызова, SSE и полное расследование через готовый EXE прошли. Результат относится к конкретной проверке, а не гарантирует будущую доступность шлюза. Старые Gemini-ключи и env-файлы не используются.

## Подключение

1. Открыть прежние **Настройки → ИИ**.
2. Выбрать DeepSeek V4 Flash и ввести собственный ключ шлюза.
3. Нажать **Проверить подключение**. Действительный запрос расходует баланс. Ограниченный тест возможностей функций может сделать дополнительные короткие запросы.
4. После успешной проверки нажать **Сохранить**. Проверенный черновик и сохранённое подключение различаются.
5. Открыть существующий чат Гермионы и отправить сообщение. Enter отправляет, Shift+Enter переносит строку.

Ключ хранится под отдельным именем `deepseek_api_key` в Windows Credential Manager. В обычной конфигурации находятся только провайдер и модель. Сохранение подтверждается чтением; при отказе сохраняется черновик и откатывается частичная замена секрета. После обычного перезапуска ключ повторно вводить не нужно, сетевой тест сам не запускается. До успешного ответа текущего процесса отображается «Настроено, не проверено».

Настройки старого облачного провайдера переводятся на DeepSeek с моделью по умолчанию. Старый Gemini-ключ не копируется новому провайдеру, не отправляется шлюзу и не удаляется автоматически. Ollama и ручной поиск остаются доступными.

## Поток данных и состояние

```text
ConnectionsPane: введённый ключ → DeepSeekClient.test_connection
→ AIState.verified_unsaved → подтверждённая безопасная запись
→ AIState.commit → открытые настройки и чат

ChatWidget → UiJob (рабочий поток) → DeepSeekClient
→ httpx.AsyncClient → /v1/chat/completions
→ choices[0].message.content → прежний пузырь ответа
```

Один `AIState` обслуживает настройки и чат. В нём нет самого ключа. История успешных реплик хранится в текущем процессе; роли приложения `user`/`model` преобразуются в API-роли `user`/`assistant`. Следующий запрос включает контекст, системную инструкцию и новое сообщение. Отмена прерывает HTTP-задачу; поздний ответ не попадает в историю. Qt-поток не выполняет блокирующий сетевой запрос.

Системная инструкция описывает Гермиону Грейнджер как вымышленный образ ИИ-помощника по OSINT: внимательное отношение к источникам, естественная русская речь, отделение фактов от предположений, без заявления о реальной человеческой личности или постоянных театральных сцен. Найденные страницы считаются недоверенными данными.

JSON отправляется в UTF-8. Ответ извлекается из `choices[].message.content`; статистика `usage` сохраняется только в безопасных числовых метаданных. Полный ответ сервера, HTTP-заголовки авторизации и ключ в сообщение об ошибке не копируются.

## OSINT и `tool_calls`

В версии 2.5 добавлен `AgentRunner` с локальным типизированным `ToolRegistry`. Явный запрос на исследование в существующем чате запускает ограниченный цикл LLM → инструменты → результат роли `tool` → LLM. Чувствительные операции запрашивают согласие, неизвестные инструменты и неверные аргументы не выполняются. Обычная переписка сохраняет прежнюю историю; её ответы приходят проверенным SSE-протоколом. Детали, пределы, происхождение находок и доступность источников — в [AGENT.md](AGENT.md).

Прежний ручной путь **Объяснить с помощью Гермионы → выбрать находки → Отправить и объяснить** сохранён. Стандартная проба подключения по-прежнему проверяет безвредный echo-цикл; полноценный агент использует только зарегистрированные адаптеры, не произвольные функции модели.

## Ошибки

Отдельно обрабатываются 401 (непринятый ключ), 402 (баланс/оплата), 403 (нет доступа), 404 (модель), 429 (лимит), временная серверная ошибка, сеть, тайм-аут, пустой или повреждённый ответ и отмена. Конфигурация и история при временной ошибке не удаляются. `Retry-After` ограничивает ранний ручной повтор; скрытых повторов и подмены модели нет.

## Доступная проверка

```powershell
python -m pytest -q
python scripts/qa_deepseek_connection.py --help
```

Живой тест запускается отдельно и не входит в автоматические тесты. По умолчанию ключ вводится через скрытый `getpass`; `--saved-key` явно разрешает использовать **только** сохранённый `deepseek_api_key`. Тест не читает старые ключи или env-файлы. Без ключа запросов нет. В отчёте есть код результата и безопасные метаданные, но нет ключа или текста переписки. Текущие результаты сборки и ограничения находятся в `VALIDATION.md`.
