# Чат: общая сетка и проверка DOM

Обновление продолжает существующие `Chat`, `AttachmentComposer`, `Sources` и
`ToolCatalog`. Четыре темы, локальный Manrope, существующая Гермиона, история,
виртуализация длинной переписки, сообщения о непрочитанном и действия источников
сохранены. Нового интерфейса или второго чата нет.

## Реальные изменения

- `chat-workspace` использует grid из растягиваемого transcript и фиксированной
  области composer. Заголовок остаётся в существующем `main-workspace`.
- Сообщения, источники, состояние задачи и composer используют общую ширину
  до 920 CSS px. Резерв scrollbar учитывается в нижней области: координаты
  текста и ввода совпадают также после открытия/закрытия dock и изменения zoom.
- Обычный абзац имеет интервал 12 px; списки, заголовки, таблицы и код получили
  согласованные интервалы. Широкие код/таблицы прокручиваются горизонтально.
- Сообщение пользователя отличается компактным фоном. Ответ Гермионы, его
  источники и действия используют общую левую линию.
- Возобновление — компактная нейтральная строка состояния, доступная только
  при `canResume`, которое production backend вычисляет по checkpoint. Кнопка
  вызывает прежний `investigation_continue`; новый checkpoint UI не создаёт.
- Операции исследования показывают текущую сводку; подробности раскрываются
  по действию пользователя. История операций не создаёт второй вертикальный
  scrollport внутри transcript.
- Inline-источники открываются страницами по шесть записей: 120 исходных
  записей не заменяются шестью и не теряются. Карточка по-прежнему открывает
  полное свидетельство. Правая панель сохраняет собственный source inspector.
- Выбор изображения находится в toolbar composer. Форматы, размер и локальность
  обработки доступны в tooltip; постоянная широкая строка JPEG/PNG/WebP удалена.
  Вложения находятся внутри общей ширины, список прокручивается горизонтально.
- Пустой textarea остаётся компактным, растёт с черновиком до прежнего лимита
  148 px, а при изменении ширины пересчитывает высоту. Enter, Shift+Enter и IME
  сохраняют назначение. Отказ отправки не очищает черновик. Фокус восстанавливается
  после запроса, если пользователь не выбрал другой элемент.
- Неинтегрированные кандидаты (`implemented=false`) не попадают в рабочий каталог.
  Реальный manifest даёт тип доступа и список поддерживаемых операций; readiness
  и последнее выполнение остаются отдельными сведениями.
  Разобранная HTML/DOM-страница, извлечённая запись, HTML-каркас и низкая уверенность
  OCR имеют разные подписи. Ни одна из них не устанавливает личность человека.

## Проверки

`scripts/qa_chat_layout.py` создаёт настоящие production PetWindow, QtWebEngine,
WebChannel и собранный React в отдельном APPDATA с пустым синтетическим vault.
Источник UI-состояния явно заменён тестовым snapshot: это проверка компоновки,
а не фиктивные OSINT-находки, live-запросы или результат агента. Реальные ключи,
история и фотографии пользователя не читаются.

Финальный прогон `output/chat-layout-qa-verified/report.json`: **304 случая,
2992 проверки DOM bounds, все пройдены**. Предыдущий прогон сохранён отдельно. Он покрывает:

- логические размеры 760×560, 1280×720, 1366×768, 1600×900, 1920×1080;
- zoom 80/100/125/150%, четыре темы, открытый/закрытый dock;
- пустой и обычный диалог, таблицу, широкий код, 1000 сообщений, 120 источников,
  выполняемую и приостановленную задачу, выбранное изображение;
- равенство ширины/координат transcript и composer, левую линию model/evidence/
  textarea, отсутствие горизонтального выхода документа, место для transcript,
  отсутствие вложенных вертикальных scrollports и фантомной колонки dock;
- ограниченное число смонтированных сообщений/источников.

Фактический DPR — 1.25. Большие размеры являются размерами виртуального окна;
это не доказательство наличия физических мониторов или проверки иных Windows
DPI. Масштабирование ОС не менялось. Снимок Qt workspace не включает отдельный
нативный Pet: его PNG сохраняется отдельно, изображения не склеиваются.

Финальная матрица повторно пройдена после короткого placeholder, отсутствия
scrollbar пустого textarea, центрирования jump-to-latest, подписей парсинга/OCR
и отображения реального manifest инструмента. Полный frontend: **85/85**,
12 файлов; TypeScript/Vite build успешен. Повтор с одним worker — 25.40 с. Логи:
`output/chat-layout-delivery-verified-tests.log`, `output/chat-layout-delivery-build.log`.
Один промежуточный параллельный запуск получил timeout старого Canvas lifecycle
теста при общей нагрузке; timeout не увеличивался, последовательный полный повтор
прошёл. Не выдаётся за новый дефект Canvas или за проверку сети.

Связанные старые backend-регрессии обновлены под публичный поиск без ключей без
внешнего браузера и исключение кандидатов из UI. Реальный SearchController
выполняет явный no-network fixture и передаёт его запись в панель.
**97/97**: `tests/test_panel.py`, `test_unified_ui.py`, `test_desktop_bridge.py`,
`test_query_router.py`, лог `output/keyless-ui-regression-verified.log`.
Финальная проверка packaged EXE и сети выполняется отдельно главным release QA.

```powershell
cd frontend
npm.cmd run test -- --maxWorkers=1
npm.cmd run build
cd ..
.venv\Scripts\python.exe scripts/qa_chat_layout.py --output output/chat-layout-new-run
```
