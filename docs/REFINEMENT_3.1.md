# Granger-OSINT 3.1 — доводка существующего продукта

Продолжается архитектура React/TypeScript + Qt WebEngine + Python из [этапа 3.0](MODERNIZATION.md). Ниже описан текущий код и отдельно — пределы имеющихся проверок. Итоговые SHA, результаты именно финального EXE и публикацию фиксирует [VALIDATION.md](../VALIDATION.md).

## Инструменты и настройки

Проблема «0 из 16» включала стартовый непроверенный каталог без автоматического discovery и неразличимые причины ошибок окружения. Исправлены автоматическая проверка при `ui_ready`, прогрессивное обновление реестра и принудительная очистка readiness-кеша при ручном обновлении. Поиск локальных исходников/окружений учитывает соседние с EXE каталоги; явно заданный ошибочный путь не заменяется молча другим checkout. Для внешнего Python при frozen-запуске временно снимается глобальный DLL search path PyInstaller, чтобы интерпретатор инструмента не загружал DLL Python/Qt из EXE.

`runtime_diagnostic` различает отсутствие исходников, интерпретатора, worker, bridge, зависимостей и базы. Готовность окружения, наличие авторизации и реальный результат вызова разделены. Число доступных инструментов зависит от локальной установки и реквизитов; фиксированное обещание «все 16 работают» отсутствует. Telegram/VK остаются недоступны без необходимых собственных секретов, Snoop — до явного включения с учётом его лицензии. Каталог показывает фильтры, допустимый вход, исправление и последнее выполнение; ручной поиск и агент используют общий контролируемый реестр.

Провайдер, модель, пути, несекретные реквизиты, бюджеты и параметры перенесены в React-настройки. Только ввод/удаление секрета открывает узкий `CredentialDialog`; ключи и сессии остаются в Windows Credential Manager. Старое полное Qt-окно настроек не возвращается при переходах современного интерфейса. Чувствительные вызовы по-прежнему требуют отдельного разрешения. Источники, фактические ошибки, сниппеты и напрямую прочитанные страницы отображаются отдельно; открытие браузера не считается получением машинных результатов.

## Предоставленные API и баланс

Подробные первичные URL, HTTP-наблюдения и ограничения: [SOURCE_RESEARCH_3.1.md](SOURCE_RESEARCH_3.1.md). Обновлён существующий официальный VK `users.get`: версия 5.199, ID/screen name, публичные поля, Bearer-заголовок, конкретные ошибки; токен не передаётся параметром URL. Положительный доступ к разрешённому профилю требует действующего собственного токена и не объявляется проверенным по одному ответу `token required`.

Looka/Murix/220VK/OK не выданы за готовые анонимные API. Avito доступен как явное открытие публичного поиска в браузере; 429 не обходится. ProxyNova COMB не интегрирован для извлечения/показа утёкших паролей. Наличие HTML или HTTP 200 не является подтверждением API либо прав автоматизации.

`gateway_balance.py` выполняет отдельный `GET https://api.aikeysforyou.com/v1/balance` без генерации. Живой запрос с сохранённым Windows-ключом вернул HTTP 200 и числовое `token_balance`; опубликован только факт получения, без остатка аккаунта. UI показывает **«Единицы шлюза (token_balance)»** и время обновления: соответствие модельным токенам, валюте или кредитам не документировано. Кеш — 60 с, минимальный ручной интервал — 10 с. Неудача не меняет статус чата; последнее успешное значение помечается устаревшим. Фактический usage, резерв бюджета и баланс остаются разными величинами. Подтверждённый размер контекстного окна модели по-прежнему неизвестен.

## Контекст и полная история

`context.py` выбирает недавние сообщения, релевантные прежние требования и ограничения. `AgentRunner` передаёт ограниченные фрагменты страниц и компактные метаданные, заменяет повтор одинакового содержимого ссылкой на сохранённый evidence ID, сокращает только завершённые группы tool calls/results и сохраняет полный протокол отдельно. `evidence_get` позволяет запросить релевантный фрагмент или диапазон исходной записи, если компактной выборки недостаточно. Первичные свидетельства и рабочий контекст модели разделены.

DPAPI-архив формата v2 больше не отсекает историю до 300 сообщений/24 контекстных реплик/60 последних сообщений. Полный имеющийся диалог сохраняется в пределах явной политики **64 МиБ**, без молчаливого удаления при превышении. Миграция сохраняет исходный шифротекст `.v1-backup`; повреждённый старый файл не перезаписывается автоматически. Ранее уже отброшенные старой версией данные восстановить невозможно. Это конечное локальное хранение, а не безграничная память или обещание отправлять весь архив при каждом запросе.

Ошибка сохранения теперь видна в интерфейсе и отменяет создание, переключение либо очистку диалога, если для операции не удалось сохранить текущие данные. Переписка остаётся в памяти, прежний ID и доступный архив сохраняются; ошибка копирования именованного архива или записи указателя также не считается успешным переключением. После успешной повторной записи предупреждение снимается. Это защита от молчаливой потери при смене диалога, а не гарантия сохранения несохранённых данных после аварии или принудительного завершения процесса. Сценарии отказа записи и восстановления проверяются в `tests/test_chat_persistence.py`.

При восстановлении истории в React-режиме больше не создаются скрытые Qt-пузырьки для каждого старого сообщения: контроллер сохраняет записи и их метаданные, видимую историю рисует существующий frontend. В локальном измерении на одном fixture из **1000 сообщений** время этого восстановления уменьшилось с **2,657 до 0,039 с**. Это результат конкретного участка и окружения, не время запуска EXE или обещание такой скорости на любом компьютере. Отдельный тест проверяет все 1000 записей, evidence ID и корректный индекс следующего потокового ответа без создания 1000 скрытых виджетов.

Benchmark `scripts/benchmark_context.py` сравнивает сохранённый Git baseline `dd3d587` с новым кодом на одинаковых синтетических источниках. Офлайн-измерение — **точные сериализованные UTF-8 байты входа**, не оплаченные токены:

| Сценарий | Весь вход до → после, байты |
|---|---:|
| Небольшой поиск | 101 184 → 70 000 |
| Повторные источники | 652 848 → 325 981 |
| Длинные страницы | 249 531 → 163 200 |

В этих fixtures совпали evidence IDs и число реальных для fixture вызовов. Четыре настоящих запроса шлюзу дополнительно сравнили финальные контексты двух сценариев: prompt tokens **14 634 → 6 194** и **7 086 → 3 914**. Ответы сохранили проверяемые коды/неопределённость; в длинном сценарии один код отсутствовал у baseline и появился после оптимизации. Это узкая проверка конкретных условий, не доказательство полной семантической эквивалентности или такой же экономии в любом OSINT-расследовании. Материалы: `output/master-3.1-qa/context-benchmark-final.json` и `context-benchmark-live.json`.

## Типографика, Гермиона и иконка

`typography.css` подключает локальный Manrope Variable с русскими буквами, включая Ё/ё, под SIL OFL 1.1. Файл не загружается из сети; происхождение и хеш — [fonts/SOURCE.md](../frontend/public/fonts/SOURCE.md). Основной текст — 15 px, на больших экранах 16 px; подписи и метаданные увеличены, усилены контраст и вес. Сохраняются тёмная палитра, клавиатура, фокус и reduced motion. Правая область подписана **«ВАША ГЕРМИОНА»**, отдельное место персонажа учитывает его исходный размер; спрайты и анимации не перерисованы.

Иконка получена точным кадрированием `grangerpet/assets/character.png` с прозрачным квадратным полем и масштабированием в ICO 16/24/32/48/64/128/256 px. Генератор воспроизводим, новая внешность не создавалась. Существующие пути QIcon и EXE resources используют новую ICO. Проверка финальной иконки в Проводнике, панели задач, Alt+Tab и ярлыке относится к отдельному EXE/Windows-сценарию. `resources/Granger-OSINT-icon.provenance.json` честно отмечает: автор/лицензия исходного фан-арта не установлены, разрешение публичного коммерческого распространения не подтверждено; библиотечные лицензии этого не исправляют.

## Пиксельный конверт с непрочитанным счётчиком

Одно локальное Qt-окно **64×48 logical px** рисует оригинальные пиксели конверта и красный круглый ступенчатый badge с bitmap-цифрами. Короткая анимация входа длится 280 мс, затем письмо статично и остаётся до просмотра. Это реализация описанной структуры; точное копирование недоступного файла референса не утверждается. Нет Windows Toast, Action Center, WinRT notification API, телеметрии или внешней службы уведомлений.

Ledger хранит только kind/message ID/conversation ID/index в `unread-messages.dpapi`. Части потока, отмена и пауза не увеличивают счётчик; ошибки обозначаются «!», не числом успешных ответов. Повторный terminal event не добавляет вторую запись. Отключение настроек скрывает представление, сохраняя непрочитанное. Нажатие открывает точный разговор/сообщение; только ACK видимых завершённых сообщений в активном текущем чате помечает их прочитанными. Открытие окна само по себе не обнуляет все диалоги.

Независимые native hit bounds решают прежнюю недоступность соседнего Qt.Tool для физического нажатия. Windows-флаги `NOACTIVATE=true`, `APPWINDOW=false` проверены на QA-окне: письмо не должно захватывать фокус или создавать отдельную кнопку панели задач. Его жизненный цикл связан с процессом Гермионы.

На изолированном **source fixture** настоящий CUA-нажим пришёл как Qt MouseButtonPress/Release, загрузил два точных DPAPI-разговора, а ACK действительно уменьшил счётчик **3 → 2 → 0** при DPR 1.25. События завершения в этом тесте синтетические, API не вызывался; это не утверждение о финальном EXE. Renderer-проверки отдельно покрывают DPR 1/1.25/1.5, прозрачность, непрочитанные записи после перезапуска, настройки и отсутствие сглаживания пикселей. Материалы: `output/refinement-qa/unread-native-independent-debug/report.json`, `pixel-letter/`.

## Что ещё ограничено

HTTP-reader не исполняет JavaScript и не обходит CAPTCHA/paywall/авторизацию. Внешний readiness не гарантирует ответ сервиса. Релевантная выборка модели не равна полному смысловому пониманию всей истории. Авторские права фан-арта не установлены. Здесь не заявлены успешная финальная EXE-проверка, чистая VM, удалённый GitHub Actions, подпись либо публикация: их фактический статус берётся только из [VALIDATION.md](../VALIDATION.md).
