# Granger-OSINT — модернизация существующего приложения

Документ описывает реализованную архитектуру и её границы. Проверки конкретной сборки, SHA-256, результаты сетевых сценариев и публикация записываются отдельно в [VALIDATION.md](../VALIDATION.md). Число успешных тестов не заменяет проверку готового Windows-приложения.

## Архитектура

Существующий Python/PySide6-проект сохранён. Его контроллеры по-прежнему владеют чатом, запросами DeepSeek, отменой задач, реестром инструментов, доказательствами, настройками и файлами. Главное окно и лаунчер показывают React/TypeScript-интерфейс, собранный Vite и включённый в пакет. Node и dev-server нужны только для разработки frontend; готовый Windows EXE использует локальные ресурсы Qt WebEngine.

Qt WebEngine выбран вместо нового Tauri/Electron-хоста, чтобы сохранить Qt event loop, работу инструментов и прозрачную настольную Гермиону. Это увеличивает пакет за счёт Chromium, но не вводит второй Python-бэкенд или отдельный HTTP-сервер для интерфейса. Текущий EXE занимает около **233 МБ**; точный размер и хеш каждой выпускаемой сборки следует брать из её отчёта. Qt WebEngine запускает штатные вспомогательные процессы Chromium; отдельный процесс на каждое уведомление не создаётся.

| Область | Реализация |
|---|---|
| Основное окно и лаунчер | `frontend/src/`: React, типизированное состояние, отдельные компоненты чата, поиска, источников, истории, Canvas и настроек |
| Контейнер интерфейса | `desktop_surface.py`: Qt WebEngine, локальная схема ресурсов, профиль и ограничения навигации |
| Связь с Python | `desktop_bridge.py`: конечный набор действий Qt WebChannel, снимки состояния и изменения сообщений |
| Чат и ИИ | Существующие `chat.py`, `ai.py`, `AIState`; OpenAI-compatible шлюз DeepSeek, потоковые ответы и отмена |
| Расследования | `agent.py`, `agent_tools.py`, `agent_journal.py`, `agent_browser.py`: реальные инструменты, свидетельства, продолжение и HTTP-чтение |
| Данные | `conversations.py`, `chat_archive.py`, `usage.py`: зашифрованные диалоги, учёт фактического usage |
| Гермиона | Прежний нативный `PetWindow`, исходные спрайты и анимации; `pet_life.py`, `pet_actions.py`, `pet_notifications.py` |

Видимое название — **Granger-OSINT**. Внутренние имена Python-пакета, `%APPDATA%/GrangerPet`, Credential Manager и IPC сохранены для совместимости с существующими установками и данными.

## Компоненты, исследование и лицензии

Исследованные документация, реальные исходники, варианты архитектуры и решения перечислены в [frontend/RESEARCH.md](../frontend/RESEARCH.md). Использованы React, Radix Primitives, Motion, Lucide, `react-markdown` и `remark-gfm`; Button/Slot-композиция адаптирована из shadcn/ui с атрибуцией. Radix обслуживает клавиатуру и фокус меню/диалогов/переключателей, Motion — конечные переходы с учётом reduced motion, Lucide — единую семью SVG-иконок.

React/Radix/Motion, Markdown-пакеты и адаптированный shadcn-код распространяются по MIT; Lucide — по ISC с включёнными уведомлениями Feather. Точные версии и integrity hashes находятся в `frontend/package-lock.json`, production notices — в `frontend/THIRD_PARTY_NOTICES.txt`. Telegram Desktop, assistant-ui, 21st.dev и Magic UI изучались как источники отдельных принципов; неподтверждённый коммерческий код, платные блоки и GPL-код Telegram не копировались в приложение.

Qt/PySide/Shiboken и Chromium имеют собственные условия лицензирования, которые не заменяются MIT-лицензиями frontend. Ссылки, сохранённые тексты лицензий Qt и сведения о внешних Python-инструментах находятся в [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md). Внешние vendor-исходники, базы и подготовленные окружения инструментов не становятся частью EXE автоматически.

## Защищённая граница интерфейса

Привилегированный WebChannel доступен только включённому в пакет frontend на origin `granger://app`. Обработчик разрешает GET к файлам внутри локального каталога сборки; выход за его границы блокируется. Перехватчик запросов разрешает локальные ресурсы приложения и штатный bootstrap Qt WebChannel. Удалённые страницы не открываются внутри этой поверхности, всплывающие окна, загрузки, выбор произвольных файлов и запрашиваемые веб-разрешения отклоняются. Профиль не сохраняет cookies и использует память для HTTP-кеша.

`bridge.ts` передаёт ID запроса, известное действие и JSON-параметры. Python проверяет типы, допустимые действия и размеры, возвращая явный результат или ошибку. Интерфейс не получает shell, `eval`, произвольный Python или общий доступ к файловой системе. Ключи не помещаются в frontend-снимки, JavaScript-bundle или журналы; ввод секретов остаётся в существующей нативной защищённой форме, хранение — в Windows Credential Manager.

Собственный локальный JavaScript интерфейса исполняется. Markdown ответов и тексты внешних страниц остаются недоверенными данными: HTML пропускается, внешние изображения автоматически не загружаются, ссылка открывается явным действием через проверку Python. WebChannel не передаётся в читаемые OSINT-страницы.

## Чат, документы и диалоги

Frontend отображает реальные сообщения существующего контроллера. Поток изменяет текущее сообщение, а не пересоздаёт весь экран на каждом токене; обновления объединяются короткими таймерами. Доступны Markdown, код и таблицы, копирование, повтор генерации, остановка и открытие ответа в Canvas. Активность инструментов строится из фактических событий: предполагаемый план не объявляется выполненной проверкой.

Canvas — редактируемая локальная копия текста с сохранением и экспортом через Python. Правка не заменяет исходное сообщение или свидетельство. Canvas и экспортированный Markdown — обычные локальные документы; защищённость диалога не означает их шифрование.

`ConversationLibrary` сохраняет именованные диалоги в DPAPI-архивах. Заголовки выводятся из расшифрованных данных в памяти; открытый индекс содержит непрозрачный ID. Прежний `chat-history.dpapi` сохранён как совместимый архив текущего разговора. DPAPI привязывает данные к текущему пользователю Windows, поэтому копирование файла другому пользователю не гарантирует возможность чтения.

Унаследованные границы `ChatArchive` остаются: **последние 300 сообщений и 24 реплики контекста**; при большом объёме число сохраняемых полных сообщений уменьшается до 60. Ограничиваются размер архива и длина записей. Это не безграничная долговременная память; при недоступности защищённого хранилища текущий сеанс может продолжать работу в памяти.

## Продолжаемые расследования и usage

Общие бюджеты шагов, вызовов, времени, токенов и страниц задаются пользователем; **0** означает отсутствие дополнительного общего предела приложения. Сохраняются индивидуальные тайм-ауты, отмена, контроль повторяющихся вызовов и ходов без новых результатов. Цель — продолжать обоснованную работу до результата, исчерпания доступных способов, отмены, ошибки или установленного бюджета; высокий номер шага сам по себе не означает завершение.

Checkpoints сохраняют цель, план, выполненные проверки, неудачи, результаты, очередь работы, протокол tool calls/results и usage. Приватное состояние атомарно записывается в `<id>.checkpoint.dpapi`; публичные нормализованные свидетельства остаются отдельным JSON. Продолжение восстанавливает состояние и избегает повторного исполнения уже завершённых одинаковых вызовов. Пауза, отмена и ошибка сохраняют собственные статусы и не называются успешным завершением.

Размер контекста физически конечен. Предыдущие протокольные группы сокращаются с сохранением сводки и ссылок на полные свидетельства вне рабочего контекста. Такое сжатие не восстанавливает данные, которые провайдер никогда не вернул, и не отменяет сетевые ограничения внешних инструментов.

`UsageLedger` хранит фактические `prompt_tokens`, `completion_tokens`, `total_tokens`, если они присутствуют в ответе API, с привязкой к запросу, диалогу и расследованию. Стабильные request IDs защищают от двойного подсчёта поздних ответов. В SQLite нет текста запросов, ответов, ключей и HTTP-заголовков. Отсутствующие счётчики остаются неизвестными; неполная статистика обозначается как неполная.

Для используемого шлюза не заявлены достоверный API-остаток средств и подтверждённый размер контекстного окна: интерфейс показывает **unknown/нет данных**. Учтённые токены и локальный резерв бюджета не объявляются остатком на счёте или точным финансовым списанием.

## Чтение публичных источников

Исследовательский `web_read` выполняет HTTP-запросы к URL, полученным из разрешённых результатов, связанных страниц или явного запроса пользователя. Проверяются схема, DNS, редиректы и публичность IP; соединение закрепляется за проверенным адресом с проверкой TLS-имени. Закрытые сети, служебные адреса, неподходящие схемы, авторизация в URL и чувствительные параметры не получают доступа.

Reader извлекает доступный HTML/plain text/JSON, основной текст, заголовки, метаданные, JSON-LD, таблицы и ссылки в пределах размера ответа. **Он не исполняет JavaScript.** Наличие Chromium в интерфейсе не превращает его в автоматический OSINT-браузер. JS-оболочка, CAPTCHA, paywall, отсутствие авторизации, 403/429 и сетевой сбой остаются ограничениями. Поисковый сниппет не считается прочитанной страницей; вывод модели и подтверждённые данные источника разделяются.

## Нативная Гермиона и уведомления

Гермиона остаётся прозрачным нативным окном с прежними исходными спрайтами, лицом, одеждой, размером, дыханием, морганием, чтением, палочкой, сном, уходом и возвращением. React не заменяет её HTML-картинкой. Главное окно резервирует отдельную область, а временная dock-позиция не перезаписывает сохранённое место рабочего стола. Ввод и реальные состояния чата/агента имеют приоритет над самостоятельными занятиями.

После настоящего завершения ответа/исследования или ошибки одно переиспользуемое Qt-окно показывает пиксельное письмо. Его конечная анимация, различающиеся состояния, дедупликация и отдельная область нажатия реализованы `QPainter`; отмена и пауза не изображаются успехом. Настройки управляют видами уведомлений и движением, учитывается reduced motion. Нажатие должно активировать существующее главное окно и точный диалог/ответ по сохранённым ID.

Маршрутизация нажатия проверена через **QTest**; показ нативного уведомления также проверялся отдельно. Это не подтверждение успешного физического клика через системное управление: попытки через transient-область CUA не подтвердили переход к точному сообщению и восстановление свёрнутого main. Поэтому физический сквозной сценарий «свернуть → завершить реальный ответ → нажать письмо → попасть к ответу» не объявляется пройденным до отдельного корректного повторения.

## Границы проверки и распространения

TypeScript build, unit/transport fixtures, QTest, PNG из реального renderer, запуск EXE и живой API-запрос проверяют разные свойства. Fixture не доказывает доступность внешнего аккаунта; показ окна не доказывает исправность каждого инструмента; программный click не равен физическому. Актуальные исходы и оставшиеся ограничения следует сверять с [VALIDATION.md](../VALIDATION.md) и материалами `output/upgrade-qa/`.

Существующие изображения Гермионы — фанатская графика с сохранённым происхождением. Granger-OSINT не является официальным продуктом Harry Potter и не получает новые права на персонажа, образ актрисы или рисунок из-за использования MIT-библиотек. Исходные artwork rights остаются самостоятельным ограничением распространения, особенно коммерческого. Новая иконка приложения не заменяет и не перерисовывает исходные спрайты.
