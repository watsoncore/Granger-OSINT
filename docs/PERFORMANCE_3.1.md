# Granger-OSINT 3.1 — performance investigation

Проверяется возможное влияние Granger-OSINT на плавность Windows. Причинная связь с лагами Telegram, Firefox или ChatGPT **не установлена**: эти приложения не управлялись, их окна, содержимое и настройки не исследовались. Исправления ограничены Granger-OSINT.

## Методика и границы

Исходная версия `d441ce9`, EXE SHA `b1362c6ef7276034fa4fcb27f1b62acb82703a38fbe33b0eac6b1988c3dc23e9`, сохранена в `dist/archive/before-performance-3.1/`; source baseline — локально в игнорируемом QA. Итоговый EXE SHA `d8994ea90eb62c600ed8218d8a4a944e69af94d7468a9c3a7fa37cbf14396ddb`, 233 999 406 байт. Кандидат с принудительным Frozen сохранён отдельно и не является финальной поставкой. Все сетевые тесты используют отдельный APPDATA, документационный example.org и сохранённый штатно ключ; ключ, число остатка, переписка обычного пользователя и приватные результаты не публикуются.

Ресурсы измеряются только у проверенных по пути PID Granger, их дочерних процессов и ранее наблюдавшихся потомков, пока совпадает время создания. Toolhelp нужен для ancestry; command lines/окна сторонних приложений не собираются. GetProcessTimes — CPU, GetProcessMemoryInfo — RSS и private commit; PDH — только отфильтрованные по собственным PID GPU Engine/GPU Process Memory. По три отрезка по шесть секунд для каждого idle-сценария; таблица — медиана медиан. Онлайн ответы недетерминированы и измерены один раз: расходы/скорость разных ответов не считаются строгим A/B benchmark. Отдельно запускался инструментированный source: счётчики Python/Qt, а не FPS GPU; его CPU не смешивается с неинструментированным EXE.

100% CPU ниже — **одно логическое ядро**, не весь ноутбук; в окружении 12 логических CPU. RSS суммирует также shared pages, поэтому это не физическая уникальная RAM. Private commit — зарезервированная системой частная память, **не private working set**; последняя отдельно недоступна. Интервал 1 с не улавливает каждую краткоживущую операцию. Состояния приложений вне Granger не измерялись и могли влиять на планирование.

## Подтверждённые причины и изменения

- Старый bridge каждые 650 мс повторно строил снимок всех сообщений, читал usage SQLite и периодически каталог истории даже без изменений. Source-счётчики подтверждают примерно 1,5–1,8 snapshot/s при обычно 0 переданных React patches/s: это лишняя Python/дисковая работа, а не доказательство постоянных React renders. Теперь сигналы Qt и существующий launcher poll сообщают только изменения; usage/history кешируются до изменения данных.
- Невидимый/minimized WebEngine перестаёт получать снимки, page visibility позволяет штатному Chromium ограничивать фоновое выполнение/RAF. Принудительные Frozen и Discarded в финальном пути не используются. DOM/черновик остаются, Canvas передаёт pending edit при visibilitychange, восстановление получает полный актуальный snapshot. Python-сеть, расследование, архив и конверт продолжают работать.
- Кандидат с ручным Frozen повысил CPU видимого окна. Изолированное source A/B при одинаковом коде/интерфейсе дало 29,44% одного ядра с Frozen против 6,20% при штатном visibility. Скрытое состояние у обоих около 6%; измерение относится к одному 6-секундному отрезку каждого source-варианта. Поэтому Frozen удалён; снижение общего CPU всех idle-сценариев не обещается. Финальный EXE проверен отдельно тремя повторениями.
- Во время streaming старый Chat пересоздавал IntersectionObserver и искал все прежние сообщения заново. Теперь observer живёт до смены активного диалога, дополняется новыми/изменившимися либо вошедшими в viewport строками и корректно очищается. Неизменённые nested state references сохраняются.
- Более 100 сообщений отображаются headless TanStack Virtual 3.14.23 с измерением высот и overscan. Полный массив, контекст, DPAPI и экспорт не обрезаны; короткий чат сохраняет прежнюю разметку. Старые сообщения доступны прокруткой и переходом поID. Нативный поиск браузера видит лишь смонтированные строки — это ограничение виртуализации.
- При отключённой реакции курсора остановлен её 85 мс timer; stationary hover не инвалидирует неизменившийся кадр, скрытый Pet не строит невидимый QImage, одинаковая QRegion не вызывает setMask повторно. Часы life/physics и видимый frame timer 42 мс (24fps) сохранены. Все12 защищённых графических файлов неизменны.

Узкий offscreen тест 200 операций ×3: stationary hover 36,406→2,444мс, hidden raster 36,903→0,325мс; 200 лишних пересборок/вызовов Qt setMask→0. Все шесть итоговых pixel hashes совпали. Это не Win32/GPU трассировка и не EXE FPS. Полный snapshot на 10 000 сообщений сам по себе не стал быстрее (63,3→67,0мс с tracemalloc); устранены его повторы.

## GPU и то, что не подтвердилось

GPU не отключался, Chromium flags, драйверы и системные параметры не менялись. В idle медиана собственных engine counters 0%, во время отдельных ответов около 11% суммы engine counters; это не процент всей видеокарты. В течение online прогонов PDH Dedicated Usage увеличивался вплоть до гигабайтов и удерживался до выхода. Это наблюдение нельзя без дополнительной driver/ETW-трассировки объявить физической резидентной VRAM или доказанной утечкой; на полном выходе собственные процессы/счётчики отсутствовали. Универсальное GPU-исправление не применялось. Нет доказательств влияния этого поведения на другие приложения; GPU memory остаётся ограничением проведённой диагностики.

Сотен перерисовок Гермионы в секунду не обнаружено: frame tick около 24/s, изменённый кадр/paint около 12/s соответствует исходным спрайтам с 12 кадрами/с. Конверт анимируется только 280 мс, затем timer остановлен. Баланс не опрашивается постоянным таймером: запуск/настройки/ручное обновление, кеш 60 с/интервал ручного обновления 10 с; инструментальная готовность не выполняется постоянно. Периодический GUI GC защищает Qt-объекты от финализации в HTTP-потоке: в исходном source-фрагменте 55,75 с суммарно 37,0 мс GC, максимум 15,1 мс gen2. Он не признан причиной чужих микролагов и гарантия GUI-thread GC сохранена.

## Процессы, тесты и поставка

У обычного EXE наблюдались bootloader + основной процесс + QtWebEngine renderer (3), два независимых приложения Launcher/Pet — 6. Закрытый лаунчер намеренно оставляет Pet, закрытое главное окно скрывает рабочее пространство. Полный выход возвращает число наблюдавшихся процессов к 0. Отдельный Windows fixture проверил собственный worker и Python-grandchild при нормальном завершении, отмене и timeout; посторонние процессы не завершались. Дополнительные циклы и итоговые проверки перечисляются ниже.

Python: 661 passed, 1 skipped (Ollama not running), 32 subtests; frontend 62 passed/9 файлов; real frozen: 59 модулей/28 ресурсов match. Streaming, DPAPI/history, bridge/state, Pixel notifications, lifeactions/physics, archive-write failures, local worker cancellation покрыты регрессиями. Чистая VM, подпись EXE и remoteActions не заявляются.

Дополнительные итоговые сценарии, публикация и хеш исходного ZIP фиксируются после завершения в release-summary.json и git-publication.json выбранного QA-набора. Полные профили, чужие окна/переписка, ключи и приватные журналы исключены.

## Итоговые проверки поставки

- Настоящий итоговый EXE: 3 цикла открытия/закрытия/отмены инструмента, 10 проверок, без оставшихся наблюдавшихся процессов после каждого выхода. Отдельный launcher lifecycle: 15 проверок при 125%.
- Длинная история содержит 1002 сообщения (501 модельный ответ); в нативном UI смонтировано 7. Через CUA проверены прокрутка к сообщениям 0/1, возврат к 999/последнему ответу и сохранение русского черновика при сворачивании. 11 автоматических проверок окна/истории/шрифта/overflow/выхода.
- Canvas-контроллер реально сохранил и экспортировал локальный тестовый документ. Реальный GET баланса финального EXE успешен; сохранены только статус, факт числа и неизвестная denomination `gateway_units`, без финансового остатка.
- Source-счётчики при бездействии: bridge snapshot 1,5–1,8/с→0/с, при примерно прежних 24 tick/с и 12 paint/с Pet. Инструментированный вариант без Frozen отделён от EXE-ресурсов.
- Обработчики IntersectionObserver/Canvas visibility/freeze очищаются при размонтировании и переключении; tests проверяют streaming без повторного наблюдения всех старых строк, offscreen фокус, возврат/скролл и bounded viewport. Сетевые задачи и завершённые уведомления при сворачивании проверены настоящими запросами.
- Область аудита: `scope-audit.json`. Системный ETW/ProcMon не включался; утверждение о соблюдении границ основано на ограниченных операциях и ревью, а не полном аудите чужих файлов/процессов.

Реальные изображения: [длинный чат и сохранённый черновик](../output/performance-qa/ui/long-chat-native.png), [ранние сообщения](../output/performance-qa/ui/early-messages-native.png). Это CUA-снимки только Granger, синтетический QA-диалог. Сводка и точные сырые измерения находятся в явно выбранном `output/performance-qa/` внутри поставляемого source ZIP. Smoke, аудит и точная Git-ревизия дополнены в `release-summary.json` / `git-publication.json`.

Финальный smoke прошёл: Launcher и Pet с новым временным профилем и PATH, ограниченным C:\Windows\System32, оба дождались React ui_ready и завершились с кодом 0. Это текущая Windows, не чистая VM.

Аудит исходников, Git, QA-текстов, EXE и распакованного source ZIP пройден: точные сохранённые значения секретов и credential patterns не обнаружены; проверены все 12 исходных графических файлов. Отдельно проверено отсутствие числа финансового остатка и приватных профилей в ZIP. Это ограниченный аудит поставки, не общий security-аудит всех зависимостей.
