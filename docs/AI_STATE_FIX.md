# Почему настройки и чат показывали разные подключения

Исправление GrangerPet 2.3 относится к конфигурации и её обмену между окнами/процессами. Поисковое ядро и графика не меняются. Итоговые тесты и результат конкретного EXE приведены в [VALIDATION.md](../VALIDATION.md).

## Причины в прежнем коде

1. `ConnectionsPane.check_connection` проверял временные поля и сохранял собственную `_verified_identity`. `_show_connection_state` мог показать «Подключено» до записи провайдера/модели/ключа: успех теста черновика принимался за сохранённое подключение.
2. `ChatWidget.set_settings` независимо вычислял `_ready` из собственной копии `settings.ai_provider` и загрузчика ключа. Тест формы эту копию не обновлял. При проверенном черновике Gemini чат мог оставаться на сохранённом `none` и запрещать отправку.
3. `SettingsDialog` закрывался без обязательного различения изменённых и сохранённых полей. После успешной проверки «Готово» мог оставить сохранённую конфигурацию прежней. Это дефект поведения интерфейса, а не доказательство ошибки пользователя.
4. `PetWindow` имел независимый `self.settings`; форма панели не обновляла эту копию. Старый `_save_position` записывал весь объект при переносе/выходе и мог вернуть старый провайдер/модель поверх уже сохранённого Gemini.
5. Launcher/IPC передавали полную структуру там, где менялись лишь размер, FPS и реакция. Такая копия могла перезаписать параметры, принадлежащие настройкам источников/ИИ.

## Исправленная цепочка

```text
Поля формы → update_draft → настоящий API test
→ verified_unsaved («Сохраните настройки»)
→ запись ключа в Windows и параметров без ключа в JSON
→ commit → changed(snapshot) для настроек и чата
→ новый клиент со свежим ключом → настоящий ответ / отдельная ошибка
```

Один `AIState` принадлежит панели и передаётся обоим окнам. Снимок содержит провайдер, модель, наличие ключа, признак сохранения, статус, контролируемую ошибку и время подтверждения. Самого ключа в нём нет.

`snapshot()` отражает ситуацию черновика, `committed_snapshot()` и `can_send` определяют реальную конфигурацию чата. Старый callback не подтверждает новый ключ или модель: проверяются поколение и идентичность конфигурации. После успешной записи `commit` сразу обновляет открытый чат. Если именно эта конфигурация была проверена, статус становится `connected`. Запись без теста даёт `configured_unverified`, а не вымышленный успех.

При перезапуске доступный сохранённый ключ разрешает отправку без повторного ввода; API-проверка сама не запускается. При неудаче записи введённые поля остаются, частично заменённый секрет откатывается. «Готово» или закрытие с изменениями предлагают сохранить, отказаться либо продолжить редактирование. Маска ключа после закрытия восстанавливается.

## Владение полями

- Форма сохраняет свои параметры и уведомляет панель и Pet через сигнал.
- `PetWindow._panel_settings_saved` обновляет настройки процесса после записи формы.
- `PetWindow._save_position` читает последнюю конфигурацию и меняет только позицию/явно изменённую реакцию, сохраняя остальное.
- `Launcher.save_preferences` читает последнюю конфигурацию и меняет только размер, FPS и реакцию.
- Launcher передаёт Pet только эти поля; обработчик IPC накладывает разрешённые поля внешности на последнюю конфигурацию, не создавая новую с остальными значениями по умолчанию.

Перенос персонажа, изменение размера и выход больше не должны возвращать `ai_provider=none` поверх сохранённого подключения.

## Проверяемые сценарии

Регрессия отдельно покрывает проверку без сохранения; запись с немедленным обновлением чата; отказ файла с откатом ключа; несохранённое закрытие; восстановление новой сессии без API-вызова; замену ключа; сетевую ошибку без удаления конфигурации; сохранение позиции и действия Launcher после записи Gemini.

Тесты используют временные профили и явно искусственные ключи/ответы. Настоящее Windows-хранилище и EXE проверяются отдельно в ограниченном пространстве, не меняя пользовательское подключение. Мок-ответ не объявляется реальным ответом Gemini. Финальные количества и живой исход следует брать из [VALIDATION.md](../VALIDATION.md).
