## P0: создание объектов

Подтверждённые причины:

1. Справочная проверка криптоадреса через bridge могла вернуть `null`, после
   чего кнопка оставалась отключённой. Проверка при сохранении теперь
   выполняется сервером независимо от предварительной подсказки.
2. При неопределённом исходе сохранения очередь правильно удерживала запись
   для повторения, но вызывающая форма могла бесконечно ждать Promise.
   Форма теперь получает ошибку, а очередь сохраняет исходный token для
   явного безопасного retry. Другие ожидающие операции сохраняют прежний контракт.
3. Созданный вручную объект мог не входить в текущую аналитическую проекцию
   или фильтр. Создание теперь атомарно включает представление всех объектов;
   ответ содержит точный entity ID и признак создания/существования. После
   подтверждения клиент снимает фильтры и показывает объект в своём расследовании.

Проверки: два новых frontend-теста до исправления воспроизводили сбои.
После исправления 241 frontend-тест прошёл; 73 целевых Python-теста графа,
bridge и криптоидентификаторов прошли. Исправленный source Qt/WebEngine прошёл 31 нативную проверку в отдельном
профиле: все 20 форм, native port connection, группы, оригинальное изображение
и сохранение композиции после перезапуска. Пять снимков просмотрены.
Первый промежуточный EXE был отклонён нативной проверкой. Финальный V11 EXE
ещё не собран и не установлен. [Receipt](validation/v11/typed-creation.json).

При нативном повторе также исправлена подвижная позиция кнопки при появлении
подсказки адреса; source harness теперь обязательно пересобирает frontend и
проверяет fingerprint. Обнаруженное игнорирование safe zones при явном Fit
остаётся задачей этапа общего layout; оно не скрывается успешным тестом
сохранения объектов.

## Источники

Строгий критерий 100 независимых интеграций сохраняется. Исследуемые API
не становятся рабочими интеграциями по результату одного транспортного probe.
Для подсчёта потребуются контракт, разрешённый доступ, нормализация,
provenance, регистрация, графовый путь, automated tests и live-проверка
исполняемого адаптера. API-ключи и source fixtures с частными данными
не публикуются.

В существующий ToolRegistry добавлен 101 новый независимый API adapter.
Это фиксированные HTTPS endpoints и allowlist полей; модель не задаёт
парсеры, URL-шаблоны или заголовки. Старый source catalog обращается к тем
же контрактам; второго реестра исполнения нет. Новые схемы подключаются
вторым шагом discovery, максимум восемь за раз. Контракты содержат typed
input/output, регион, условия, provenance, timeout/cache/rate policy и
отдельную историю фактических ответов без секретов и запросов пользователя.

Общий live-повтор через текущий ToolRegistry: **100 из 101** получили свежие
непустые ответы, прошли normalization → typed graph → encrypted save/reopen
и повторное добавление без дублей. В первом прогоне NVD завершился timeout; в повторе NVD прошёл,
а Copernicus завершился timeout. В каждом полном повторе засчитано 100;
неуспешный провайдер этого прогона исключён. [Инвентаризация и ограничения](V11_SOURCE_INVENTORY.md),
[последний receipt](validation/v11/source-pipeline-current.json). Это backend-проверка,
не подтверждение native preview или итогового Windows EXE.

Целевые тесты framework: 389 passed; после уточнения повторного исследования
и материала интерфейса дополнительно 360 целевых тестов прошли. Полный Python suite на этом этапе:
2559 passed, 1 skipped, 32 subtests passed. Проверка секретов source +
установленного V10 + Git history: 7557 payloads, нарушений нет.
Проверка итогового V11 EXE ещё предстоит.
