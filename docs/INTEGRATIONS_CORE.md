# Поисковое ядро и локальные источники GrangerPet

Проверено на существующих исходниках в `Hermi_osint` 27 октября 2026 года. Этот документ дополняет `INTEGRATIONS.md`; сведения о платформах, архивах и Gansar находятся там.

## Как выполняется поиск

`grangerpet/engine/controller.py` принимает `SearchQuery`, определяет категорию и запускает максимум **два источника одновременно**. Legacy-библиотеки работают в отдельных процессах Python 3.12 из `.toolenvs/<источник>/`, а не в интерпретаторе PySide6. Системные терминалы и интерфейсы внешних инструментов не открываются.

Каждый запрос передаётся дочернему процессу через stdin JSON; результаты возвращаются по stdout JSONL. Пароли, сессии и токены не попадают в аргументы командной строки. Текстовый вывод и логгеры библиотек отключены, временные отчёты ограничены отдельной временной рабочей папкой. Оригинальные исходники и базы не переписываются. Настройщик строит устанавливаемые пакеты во временных копиях.

Число проверяемых площадок ограничено настройкой 1–50 на запрос и распределяется между источниками никнеймов. Каждый такой инструмент использует максимум три параллельных HTTP-проверки. Повторные HTTP-попытки Social Analyzer ограничены тем же бюджетом. У каждого процесса есть timeout; отмена прекращает процессы. В Windows используется Job Object с `KILL_ON_JOB_CLOSE`, включающий дочерние процессы. Сетевые ограничения, CAPTCHA и блокировки не обходятся.

В замороженном приложении перед запуском внешнего Python временно сбрасывается `SetDllDirectoryW`, затем восстанавливается. Из среды дочернего процесса убираются пути PyInstaller, `PYTHONHOME` и служебные переменные загрузчика. Это предотвращает смешивание DLL встроенного Python 3.14 и инструментов Python 3.12. Подход соответствует [документации PyInstaller](https://pyinstaller.org/en/stable/common-issues-and-pitfalls.html#launching-external-programs-from-the-frozen-application).

Результат содержит `id`, `title`, `type`, `platform`, `url`, `description`, `date`, `details`, `status`, `sources`. Совпадающие URL профилей объединяются с атрибуцией нескольких инструментов. Разные площадки с одинаковым никнеймом не объединяются в человека. Баланс, метка, транзакции и другие самостоятельные факты сохраняются отдельно даже при общем URL обозревателя. Итоговые данные заменяют предварительные сведения того же источника; подтверждения сохраняются и после достижения лимита карточек.

Ошибки одного инструмента не останавливают остальные. Возможны `queued`, `running`, `complete`, `empty`, `error`, `unavailable`, `auth_required`, `timeout`, `cancelled`. Happy запускается только при ненулевой реальной выдаче; пустой ответ и отмена возвращают Idle.

## Среды и воспроизводимость

Настройка уже загруженных компонентов:

```powershell
.\.venv\Scripts\python.exe scripts\setup_sources.py --groups maigret,blackbird,holehe,snoop,social_analyzer
```

Используется Python 3.12.14 для legacy-групп, отдельный от GUI. Зафиксированные установленные версии сохраняются внутри каждого окружения в `installed-requirements.txt`, а результат настройки — в `output/integration_setup_core.json`.

Для сборки Go-моста нужен Go. В текущей рабочей среде установлен отдельный официальный Go 1.27.3 из архива Windows amd64 с проверенным SHA-256 `f26081f438319757f8a1b46d7d0b2c5ec7583d4038e485e0aa725cfde7885fff`; системный PATH не изменялся. Компилятор находится в `.toolenvs/go/bin/go.exe`, сборочный кэш — в `.toolenvs/go-cache/`. Мост собран из существующего PhoneInfoga с `-mod=readonly` и находится в `.toolenvs/phoneinfoga/phoneinfoga-bridge.exe`. Исходник моста — `scripts/phoneinfoga_bridge.go`.

Если программа перенесена в отдельную папку, укажите папку исходников/подключений в настройках. Папки инструментов и `.toolenvs` не копируются внутрь `GrangerPet.exe`. Запуск Launcher, персонажа, Dork Builder и браузерного поиска не требует этих сред. Отсутствующий источник отображается как недоступный и не подменяется URL-заготовками.

## Что проверено на живых источниках

Машинный отчёт: `output/source-live-core.json`.

- Maigret: публичный `octocat`, два GitHub/Gist-ответа HTTP 200.
- Blackbird: тот же открытый тестовый аккаунт, две настоящие проверки GitHub API.
- Social Analyzer: настоящая открытая страница GitHub, один найденный профиль с эвристическим статусом.
- Snoop: одна настоящая проверка GitHub, HTTP 200 и `найден!`.
- Holehe: один GET Gravatar для синтетического `grangerpet-test@example.com`; честный пустой ответ, без регистрации/восстановления пароля.
- PhoneInfoga: офлайн-разбор зарезервированного примерного номера `+12025550123`, подтверждены US и формат E.164. Сеть для этого не нужна.

Это ограниченные проверки конкретных площадок, а не утверждение о работоспособности всей многотысячной базы. Живая выдача Google API без пользовательского ключа не проверялась. Платформенные подключения с авторизацией и внешний LLM описаны отдельно.

`tests/test_engine.py` проверяет классификацию, сохранение разных фактов на одном URL, дедупликацию и атрибуцию, окончательное обновление частичных данных, лимиты, конкуренцию, отмену, реальные скрытые дочерние процессы с тестовым протоколом, timeout и ограничение вывода. Тестовые transport-ответы явно отделены от живых проверок выше.
