# Structured tools in the existing desktop UI

The existing search workspace reads `Tool.manifest.input_schema`. Object schemas show typed fields and dispatch `tool_run` with an `arguments` object. Existing text tools retain their `query` protocol. Optional empty fields are omitted; numbers, JSON arrays/objects, enum and boolean values are validated before dispatch. The backend remains authoritative. Unimplemented catalogue candidates are absent from the tool selector.

The existing evidence dialog now renders local TikTok ID timestamps, role classification, ShadowFinder grid/candidate results, evidence graph pages and offline visual model outputs. Shadow cells use a bounded coordinate SVG without a map tile service; it renders at most 200 valid polygons. Classification and graph entities use 20-row pages. Graph navigation calls the actual backend tool and preserves its request filters. It does not infer personal identity from a shared username. Model predictions are labelled geographic hypotheses; raw scores are not confidence percentages. Matching displays actual keypoint/match/inlier counts and geometry state rather than a claimed location.

The existing tool settings contain an optional visual-model disclosure. Installed files and a verified runtime have distinct states. Installation, cancellation and runtime probing use explicit bridge actions. Received bytes are labelled with the current artifact, never presented as a percentage of the entire installation. No model is automatically downloaded by this UI. The restricted Nuclei preference defaults off and describes its confirmed-scope HTTP HEAD limitation; this UI does not install the CLI.

Follow-up: model candidates also have a bounded SVG coordinate grid with ranked markers (at most 20 finite in-range coordinates), explicitly labelled hypotheses without a map tile service. The evidence dialog displays the supplied local raster data preview, rejects remote URLs, and does not load an external image. Optional runtime removal dispatches `visual_remove` for native backend confirmation; its button is disabled while installing, loading, running or removing. Related tests passed 19/19 and the production build passed (`frontend-visual-map-tests.log`, `frontend-visual-map-build.log`).

Sequential-pipeline follow-up: `visual_geoint_comparison` evidence renders the measured great-circle distances and a documented 100 km screening flag, with explicit warnings that edited EXIF and model agreement do not establish location. The existing structured input form handles the pipeline's methods, OCR preference and optional shadow parameters. Related frontend tests passed 20/20 and the production build passed (`frontend-visual-pipeline-tests.log`, `frontend-visual-pipeline-build.log`).

Validation: `npm test -- --run` passed 101 tests in 13 files; `npm run build` passed TypeScript and Vite production compilation. Logs: `output/integrations19/frontend-19-ready-tests.log`, `frontend-19-ready-build.log`. The existing Vite large-chunk warning remains. Tests use bridge fixtures and do not claim live model inference, native confirmation or packaged executable verification. Backend and packaged-app verification belong to the main integration run.
