# Контекст и сохранность данных в 3.1

Изменения относятся к существующим Python-контроллерам Granger-OSINT. История, исходные свидетельства и восстановимое состояние исследования сохраняются отдельно от сокращаемого запроса модели. Нулевые пользовательские бюджеты по-прежнему означают отсутствие соответствующего общего лимита; оптимизация не вводит новый предел числа шагов.

## Что изменено

| Область | До этой правки, baseline `dd3d587` | После правки |
| --- | --- | --- |
| Архив сообщений | Последние 300 сообщений; при большом JSON — последние 60; текст при чтении ограничивался 120 000 символами | Все допустимые сообщения, полный текст и все допустимые evidence ID сохраняются без этих усечений |
| Контекст в архиве | Последние 24 реплики | Сохраняется весь переданный контекст; архив не сокращается ради модельного запроса |
| Обычный запрос модели | Последние 24 реплики текущего контекста и новый вопрос | Рабочая выборка: последние реплики, релевантные старые сведения и существенные требования пользователя; исходная история остаётся целой |
| Описание инструментов | Подробный каталог повторял часть уже переданных tool schemas | Schemas остаются; системный текст дополнительно перечисляет только недоступные инструменты и их причины |
| Результаты инструментов | Повторялись расширенная provenance, сниппет и часть текста страницы; завершённые группы хранились до большого порога контекста | Краткая provenance, релевантные выдержки, ссылка на уже переданное идентичное содержимое; обычно две последние полные протокольные группы и рабочая память |
| Протокол расследования | Checkpoint сохранял рабочие сообщения, из которых старые группы уже могли быть удалены | Дополнительно сохраняется полный `protocol_archive`; сокращение рабочего запроса не удаляет вызовы и ответы из этого архива |
| Возврат к первоисточнику | `evidence_get` по точному ID | Тот же инструмент поддерживает `focus`, `offset` и `length` для ограниченного чтения нужного фрагмента без нового сетевого обращения |

Рабочая память содержит цель, план, выполненные этапы, неудачные проверки, оставшиеся действия и ссылки на свидетельства. Приоритет получают релевантные сведения и записи с противоречивыми наблюдениями. Выдержки сохраняют исходные формулировки и степень подтверждённости; поисковый сниппет не становится прочитанной страницей или доказанной личностью.

Повтор идентичного содержимого не меняет `evidence_id`, источник и время наблюдения. Изменившиеся первичные данные не считаются идентичными. Кеш `evidence_get` проверяется против текущей записи: более позднее противоречивое наблюдение не заменяется старой сохранённой версией. Диапазоны чтения валидируются; максимальный фрагмент — 6000 символов. Это доступ к сохранённой записи, а не разрешение произвольно читать файл или URL.

## Хранилище и миграция

`chat-history.dpapi` и именованные диалоги остаются защищёнными DPAPI вошедшего пользователя Windows. Формат архива версии 2 совместим с чтением прежних JSON-структур внутри DPAPI. Перед первой миграцией сохраняется исходный **шифротекст** `.v1-backup`; при загрузке старого именованного диалога его исходный файл также получает резервную копию. Названия диалогов не переносятся в открытый индекс: там остаётся непрозрачный ID.

Вместо политики удаления сообщений действует техническая граница **64 МиБ JSON UTF-8 на архив**. При превышении сохранение сообщает об ошибке и оставляет прежний файл целым. Это не бесконечное хранилище и не обещание восстановить сообщения, уже удалённые прежними версиями. Для таких сообщений возможен только поиск существовавших ранее резервных копий.

Исходные evidence, исполнения, кеш вызовов, ожидающие действия и протокол исследования находятся в DPAPI checkpoint. Его существующая граница — **32 000 000 байт JSON**; публичный нормализованный журнал свидетельств сохраняется отдельным JSON. Политики защиты различаются: публичный журнал и экспортированные документы не объявляются зашифрованными архивами чата.

Для списка разговоров заголовки и количество сообщений кешируются в памяти по размеру и времени изменения файла. Периодическое обновление списка не расшифровывает все неизменившиеся большие архивы заново.

## Физические и пользовательские пределы

Модельный запрос остаётся конечным. Для рабочего контекста агента используется цель до 24 000 символов сериализованной истории, при сохранении существующего технического потолка `max_context_chars` — 64 000 по умолчанию. Это локальная политика подготовки запроса, **не заявленный размер контекстного окна DeepSeek** и не остаток средств. Целые assistant/tool-группы сокращаются совместно: одиночный tool-ответ без соответствующего вызова не отправляется.

Обычная рабочая выборка ограничена по объёму, включает текущий вопрос полностью в пределах допустимого размера ввода и выбирает релевантные старые сведения. Она не заменяет постоянный архив. Исчерпание явно установленного пользователем бюджета, отмена, тайм-аут запроса и обнаружение повторяющегося цикла сохраняют прежние отдельные причины остановки. Продолжение сохраняет ID расследования, накопленные расходы, evidence и завершённые проверки.

Оценка байтов или локальный резерв бюджета не записываются как оплаченные токены. Prompt/completion/total берутся только из фактически возвращённого gateway `usage`; отсутствие отдельных полей остаётся неизвестностью.

## Воспроизводимый benchmark

Скрипт: [`scripts/benchmark_context.py`](../scripts/benchmark_context.py). Baseline загружается из Git-коммита `dd3d587`, новая реализация — из рабочего дерева. Источники полностью синтетические, используют `example.org`, не содержат персональных данных и не обращаются к OSINT-сервисам.

Для двух реализаций исполняется одинаковая заранее заданная последовательность инструментов. Offline-часть измеряет точный суммарный объём сериализованных входов в UTF-8, проверяет протокол и сравнивает evidence ID/количество вызовов/сохранность первичного текста.

| Сценарий | Вызовы инструментов | Evidence | Входные байты всех шагов, до → после |
| --- | ---: | ---: | ---: |
| Небольшой поиск | 2 | 16 | 101 184 → 70 000 |
| Повторные упоминания источников | 10 | 80 | 652 848 → 325 981 |
| Длинные страницы | 6 | 6 | 249 531 → 163 200 |

Во всех трёх сценариях до/после совпали количество выполненных инструментов и полный набор evidence ID; первичные тексты сохранились. Байты из этой таблицы **не являются токенами** и не пересчитываются в денежную экономию.

Live-часть сделала **четыре настоящих gateway-запроса**: по одному итоговому запросу до и после для двух сценариев. На шлюз повторно передавался конечный рабочий контекст после синтетической последовательности инструментов. Планирование всех предыдущих шагов в этой live-части не выполнялось моделью; поэтому это **сравнение итоговых модельных входов**, а не измерение полной стоимости автономного реального расследования.

| Итоговый запрос | Prompt до → после | Completion до → после | Total до → после |
| --- | ---: | ---: | ---: |
| Повторные упоминания | 14 634 → 6 194 | 193 → 137 | 14 827 → 6 331 |
| Длинные страницы | 7 086 → 3 914 | 191 → 267 | 7 277 → 4 181 |

Значения получены из настоящего `usage`, а не оценены локальным токенизатором. В первом сценарии обе версии вернули контрольный код `AXIOM-7` и сохранили неопределённость. Во втором обе сохранили `ORIGIN-11`, а новая версия дополнительно извлекла `PRISM-29` из дальней части первичного текста; исходная версия его не включила. Неопределённость сохранилась в обоих ответах. Это ограниченные автоматические проверки контрольных фактов, а не полноценная экспертная оценка любых выводов модели.

Локальные отчёты, исключённые из публикации Git:

- `output/master-3.1-qa/context-benchmark-final.json` — offline-проверка окончательного backend-кода.
- `output/master-3.1-qa/context-benchmark-live.json` — четыре реальных ответа usage и проверки контрольных фактов.
- `output/master-3.1-qa/readiness-before.json`, `readiness-after.json`, `runtime-before.json` — отдельный offline-аудит окружений; эти отчёты не означают успешный сетевой поиск всеми инструментами.

Команды повторения:

```powershell
python scripts/benchmark_context.py
python scripts/benchmark_context.py --live --scenarios repeated_sources,long_pages --output output/master-3.1-qa/context-benchmark-live.json
```

`--live` выполняет оплачиваемые API-запросы с уже настроенным ключом, не записывая ключ, заголовки или тела ответов в отчёт. Повторный запуск может дать другой completion usage и другой текст; приведённые числа относятся только к зафиксированному прогону.

## Проверки реализации

`test_context.py` проверяет релевантные старые требования за пределами 24 реплик, конечный рабочий объём, чтение хвоста первичного текста, точный `evidence_id`, неизменность оригинала и различение повторного/изменившегося содержимого. `test_agent_lifecycle.py` проверяет продолжение, кеш, отмену, валидность протокола и сохранение всех 36 вызовов с ответами при сокращении рабочего контекста.

`test_chat_archive.py` использует настоящий Windows DPAPI: 620 сообщений, длинный текст, более 200 evidence ID, исходный и именованный legacy-архив, резервные копии, а также сохранность предыдущего файла при превышении storage policy. Focused-прогон связанных backend/Qt-тестов: **96 passed**; отдельный окончательный прогон архивной миграции: **6 passed**. Полная проверка сборки и реального EXE описывается отдельно в общем отчёте валидации.
