# Локальные источники GrangerPet 2.0

Основной Windows EXE включает интерфейс, персонажа, Google Dork Builder и мост источников. Он не включает загруженные сторонние репозитории, их базы, Go toolchain или все Python-зависимости. Это сохраняет независимость Qt, разумный размер EXE и оригинальные пользовательские данные.

Папка источников определяется относительно EXE, его родительской папки или параметром **«Папка подключений»**. Для текущего проекта подходит корень `Hermi_osint`. Пути `.toolenvs/<group>` вычисляются относительно этой папки; абсолютный путь разработчика в код не встроен. Пользовательский параметр Python переопределяет автоматический выбор и должен указывать на совместимое окружение с нужными зависимостями.

## Подготовка

```powershell
python scripts/setup_sources.py --audit
python scripts/setup_sources.py --groups platforms,blockchain
python scripts/setup_sources.py --groups maigret,blackbird,holehe,social_analyzer
```

Для всех доступных групп предусмотрен `--groups all`; дополнительный Snoop запускается в поиске только при явном выборе. Скрипт использует существующие папки исходников, а не клонирует новые. Он создаёт изолированные окружения Python 3.12; при наличии `uv` совместимый Python подготавливается автоматически. Без `uv` нужен установленный Python 3.12 или `--python` с путём к нему. Зависимости приложения в `.venv` не заменяются.

Локальные Python-пакеты собираются из временных копий исходников. Telethon 1.42 в имеющемся архиве не содержит сгенерированных TL-классов: его штатный генератор строит их из включённых схем во временной папке, после чего пакет устанавливается в окружение. Оригинальный архив не заменяется. Файлы `installed-requirements.txt` фиксируют фактически установленные версии; состав групп задан в `scripts/source_requirements.json`.

Скрипт не запрашивает и не сохраняет ключи. Отчёт установки находится в `output/integration_setup.json`. Отсутствующий интерпретатор, библиотека, исходник или внешний бинарник приводит к статусу недоступности источника; результаты не подменяются.

Для PhoneInfoga используется отдельный Go-мост из `scripts/phoneinfoga_bridge.go`, собираемый против существующего `phoneinfoga-master`. Если Go уже доступен в PATH или `.toolenvs/go/bin/go.exe`, скрипт собирает `.toolenvs/phoneinfoga/phoneinfoga-bridge.exe`. Можно передать `--go` с путём к компилятору. Полная программа PhoneInfoga и отдельное окно не запускаются.

Окружения `.toolenvs` рассчитаны на подготовку на этой машине. Простое копирование Windows venv на другой компьютер не гарантирует переносимость: его базовый интерпретатор может находиться отдельно. На другом компьютере запустите подготовку с имеющимися исходниками. Сам GrangerPet.exe запускается без установленного Python; это не означает наличия всех необязательных внешних движков.

## Платформы и архивы

| Направление | Реальный вызов | Авторизация | Возвращаемые сведения и границы |
|---|---|---|---|
| Instagram | локальный Instaloader 4.16, `Profile.from_username` | Анонимно, пока платформа разрешает; при необходимости собственная сессия | Доступные метаданные профиля: имя, описание, счётчики, признак приватности и публичная ссылка. Файлы, приватные публикации, подписчики и контакты не скачиваются. |
| Telegram | локальный Telethon 1.42, `get_entity`, `iter_messages` | API ID, API hash, уже авторизованная StringSession | Публичное имя/канал и до трёх доступных публичных публикаций. Приватные приглашения и чаты не исследуются, вход через OTP автоматически не запускается. |
| ВКонтакте | локальный vk_api 11.10.1, официальный `utils.resolveScreenName` и `users.get`/`groups.getById` | VK access token с разрешёнными правами | Публичные сведения одного пользователя или сообщества. Используется только vk_api; vkbottle изучен, но не запускается параллельно ради одинаковых запросов. |
| Веб-архив | локальный WaybackPy 3.0.6, CDX API `snapshots()` | Не нужна | До десяти существующих снимков с датой, URL, MIME и кодом ответа. Новое архивирование не инициируется. |

Подключения задаются в раскрывающейся секции панели. Telegram API hash/StringSession, VK token и Instagram cookies сохраняются через защищённое хранилище приложения. Instagram принимает JSON-словарь cookies собственной разрешённой сессии с `sessionid` и `csrftoken`; значение cookies нельзя публиковать. Имя авторизованного аккаунта задаётся отдельно. Файлы Instaloader pickle не загружаются, браузерные cookies скрыто не извлекаются.

Для VK не вызывается парольная авторизация; конфигурация библиотеки хранится только в памяти. Для Telegram отключены получение фоновых обновлений, автоматическое ожидание FloodWait и повторные подключения. WaybackPy сохраняет свой реальный конструктор и парсер CDX; его HTTP-транспорт ограничен таймаутом и единственной попыткой, поскольку исходный транспорт не задаёт таймаут.

## Внутренний блокчейн-движок

Адаптер вызывает настоящий `Gansar-main/app/aggregator/analyzer.py::analyze_address`, получает `AddressReport` и преобразует наблюдения в общие карточки. CLI, HTML/PDF-экспорт, браузер, графы и отдельный интерфейс Gansar не запускаются. Установлены только зависимости этого пути: Pydantic, HTTPX, Selectolax, NetworkX, Rich, PyYAML и ens-normalize. Playwright/Chromium и PDF-библиотеки для поиска не нужны.

Исходный движок распознаёт Bitcoin, Dogecoin, TRON, TON, EVM и Solana; доступность баланса и истории зависит от конкретного провайдера и сети. Для EVM при неоднозначности применяется Ethereum или выбранная вручную сеть. Поддержана проверяемая прямая резолюция `.eth`: при отсутствии подтверждения адрес не подставляется. Существующие ресурсы `app/attribution/assets` читаются на месте и не копируются в EXE. В локальном дереве при аудите обнаружены 11 файлов атрибуции общим размером около 10,8 MB; пользовательские базы и сохранённые исследования не удаляются.

Выводятся предоставленные источником балансы, транзакции, активы, метки и контрагенты. Точные десятичные суммы, даты, исходные URL, покрытие и здоровье провайдеров сохраняются. Метки, историческое/неизвестное владение и связи помечены как требующие проверки. Транзакционное взаимодействие не доказывает общий контроль кошельков или личность человека. При большом числе переводов категории чередуются, чтобы не скрывать все сведения об активах и связях за историей транзакций.

Время каждого провайдера ограничено, общий дедлайн поиска контролируется worker-процессом. Дополнительно адаптер ограничивает число исходящих HTTPX-запросов параметром приложения (5–50, обычно 20). Достижение лимита отмечается как неполное покрытие. Каждые две секунды доступны промежуточные наблюдения; отмена завершает изолированный процесс и его дочерние процессы.

Некоторые провайдеры принимают собственные ключи через переменные окружения исходного Gansar, например `TONAPI_KEY` и `ETHERSCAN_API_KEY`; без них используются реально доступные публичные методы. Наличие API-ключа не гарантирует доступ ко всем методам. Приложение не генерирует транзакции и не подменяет отсутствующую выдачу.

## Остальные локальные движки

Аудит, адаптеры, лицензии и ограничения поиска никнеймов, email и телефона описаны в [INTEGRATIONS_CORE.md](INTEGRATIONS_CORE.md). Все источники работают через единый контроллер, с максимум двумя одновременно выполняющимися инструментами, ограничением проверок и отдельными таймаутами. Секреты передаются дочернему процессу через stdin, не через командную строку. Логи сторонних инструментов в интерфейс и журналы GrangerPet не выводятся.

## Что проверено

- Окружения `platforms` и `blockchain` подготовлены на Windows под Python 3.12.14; реальные локальные модули импортируются.
- Живой WaybackPy-запрос `https://example.org/` вернул пять существующих архивных снимков. Запрос не имитировался.
- Живой вызов внутреннего Gansar для публичного Bitcoin genesis-адреса вернул on-chain наблюдения. Проверен лимит 12 HTTP-запросов, предупреждение о неполной истории и нормализация результатов. Отчёты: `output/source-live-platforms.json` и `output/source-live-platforms-latest.json`.
- Анонимный запрос Instaloader к публичному профилю был действительно выполнен, но источник отклонил/не выполнил запрос (`ConnectionException`). Живая выдача Instagram не подтверждена.
- Telegram и VK без настроенных учётных данных корректно возвращают требование авторизации. Запросы с действующей пользовательской сессией/токеном не проверялись.
- `tests/test_platform_adapters.py` проверяет публичные идентификаторы, отказ от приватных ссылок, границы авторизации и нормализацию. Тестовые метаданные профиля и блокчейн-объекты явно заданы как fixtures; они не выдаются за живую выдачу.

Проверки готового EXE и интерфейса описываются отдельно в `VALIDATION.md` для соответствующей сборки.
