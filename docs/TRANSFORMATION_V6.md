## A. Architecture Audit

Исходный HEAD — `425426f`. Рабочая копия была чистой. Сохранились Python/PySide6 6.11.1, Qt WebEngine, React/TypeScript, Canvas2D, два worker для раскладок, шифрованные ревизии CanvasStore и очередь с durable ACK. Изучены отчёты V3, V4, V5, актуальный frontend bundle, spec и release gates.

На исходном EXE V5 повторён нагрузочный сценарий. Полотно не принимало drop или картинки из буфера. Изображение по кнопке получало миниатюру 128 px, которая записывалась в каждую последующую ревизию графа. Renderer просматривал все узлы для видимости и hit testing, пересчитывал мини-карту и измерял повторяющиеся строки. В production выполнялась сериализация QA-геометрии на каждом кадре. Тест нового Qt drop воспроизвёл отсутствие доставки файлового события в DOM.

## B. Visual Transformation

Новая оболочка использует глубокий графит, несколько уровней поверхности, отражающие кромки, тёплый акцент и локальное свечение выбора. Общие tokens покрывают панели, формы, списки, настройки, историю, текстовый Canvas, граф и просмотр изображений. Сохраняются четыре темы и локальный Manrope с кириллицей. Шрифт и вспомогательные библиотеки остаются из существующего lockfile.

Стекло реализовано градиентами и тонкими кромками. Пользователь выбирает полные, уменьшенные или выключенные эффекты. Уменьшенное движение учитывает настройки приложения и системы. Плотность переключается из общей верхней панели.

## D. Media System

Файловый выбор, локальный путь, drop, снимок из буфера, публичный HTTPS URL и фото из сведений об объекте обращаются к общему импорту AttachmentStore. Подготовка изображения возвращает content-addressed ID. Привязка к расследованию затем проходит через существующую очередь с проверкой revision и подтверждением записи.

Файловый drop принимает Qt. DOM получает одноразовый token и координаты, преобразованные в мировую систему через актуальную камеру. Карта сохраняется в точке отпускания. PNG из Windows Clipboard считывается через Qt. Браузерные разрешения на clipboard и удалённые URL остаются ограниченными. Тесты временно подставляют QA-снимок в системный буфер и восстанавливают прежнее содержимое, если пользователь его не изменил.

Оригиналы сохраняются зашифрованными с SHA-256 и дедупликацией. Новые документы хранят ссылки и метаданные. Для загрузки превью используются ограниченный пул и кеш декодированных изображений с максимумом 64 записей. Вычисления Pillow идут вне GUI-потока. Проверяются тип, разрешение, EXIF orientation, размер и целостность файла.

Карточки учитывают пропорции, допускают resize, вписывание и заполнение без изменения оригинала. Двойной щелчок открывает просмотрщик с увеличением, прокруткой и полноэкранным режимом. Нативное окно оригинала предоставляет реальный масштаб пикселей, перемещение и копирование. У объекта может быть несколько связанных изображений. Отвязка сохраняет исходное вложение и evidence.

Публичная загрузка использует существующий pinned transport. Проверяются HTTPS, DNS-адреса, каждый redirect, MIME, размер и robots policy. URL и конечный адрес сохраняются как происхождение. После импорта просмотр использует локальное вложение.

## E. Graph Engine

Для этой поставки выбран существующий Canvas2D. Он поддерживает текущие типы, редактирование, размеры, финансовые связи, semantic zoom и worker layouts. Данные и координаты остаются в общей модели. Введены пространственный индекс видимых карточек и hit testing, ограниченный кеш измерений текста, кеш геометрии мини-карты и адаптивное число сегментов рёбер. Во время drag меняются только выбранные координаты. После отпускания сохраняется дельта. Скрытое полотно не запрашивает кадры. Подробная QA-телеметрия включается только в изолированном прогоне.

Мини-карта отражает реальные размеры, центр, группы и выбранный объект. Она скрывается на узком полотне. Сохранены режимы manual, hierarchical, radial, types, communities, timeline, wallet, flow, counterparties и paths.

## G. Performance

Ниже сравниваются два настоящих EXE на одном ноутбуке. Прогон использует одинаковый сценарий, culling и модели. Искусственные узлы и граф из публичных наблюдений указаны отдельно.

| Набор | Узлы | V5 рисование p50 / p95, мс | V6 рисование p50 / p95, мс | V6 событие → кадр p95, мс |
|---|---:|---:|---:|---:|
| Синтетика | 50 | 3.4 / 9.2 | 2.7 / 6.8 | 12.8 |
| Синтетика | 100 | 3.0 / 4.3 | 2.8 / 3.9 | 12.8 |
| Синтетика | 500 | 4.8 / 6.2 | 4.3 / 5.4 | 11 |
| Синтетика | 1000 | 6.7 / 8.2 | 5.85 / 7 | 9.3 |

| Наблюдения TON | 424 | 1.2 / 1.9 | 1.1 / 2.8 | 4.3 |

Paint измеряется в WebEngine. Event-to-paint начинается в JS handler и исключает задержку IPC. Active frame intervals фиксируют только интервалы активных кадров, их reciprocal не является FPS всей сессии. p99, время открытия, CPU, RSS/private memory и доступные счётчики GPU содержатся в JSON. В source-прогонах ProcessSampler не смог привязать дерево Python, поэтому нулевые показатели CPU/RAM из этих прогонов исключены из агрегата.

Сравнение effects full/reduced/off в source и на каноническом EXE проводилось отдельными процессами. Разброс времени кадров требует повторных серий для причинного вывода о цене glow. Тест на отдельном маломощном устройстве и принудительное назначение integrated GPU не выполнялись.

## L. Remaining Limitations

Устойчивые 60 FPS во всех сценариях, длительный memory soak, принудительный CPU rendering и отдельный ноутбук с iGPU требуют дополнительной проверки. Результаты нагрузочного прогона отражают доступную машину и конечную серию жестов.

Импорт публичных изображений ограничен общим сетевым бюджетом 2 MB. Локальные изображения ограничены 20 MiB и 24 млн пикселей. Поддерживаются статичные JPEG, PNG и WebP. Просмотр оригинала выполняется в отдельном нативном окне.

Экспорт расследования в JSON сохраняет ссылки на вложения. Самостоятельный перенос JSON на другой компьютер требует переноса защищённого хранилища вложений. Отдельный переносимый пакет расследования с изображениями в V6 не создан. Автоматическое назначение фото подтверждённой личности отсутствует, provenance и статус источника сохраняются.
